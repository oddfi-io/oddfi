# 0. 通用约定

## 0.1 状态标注

- `[已有]`：直接复用 `oddfi-backend` 真实接口（路径与字段不动，见 `01. oddfi-backend-openapi.yaml`）
- `[新增]`：Admin 看板专用，本次需后端新设计

## 0.2 Base URL

```
admin-api 服务（新增）：       /api/v1/admin
web-api 服务（已有，复用）：   /  （原路径）
```

## 0.3 通用响应

新增 `admin-api` 统一包装：

```json
{
  "code": 0,
  "message": "ok",
  "request_id": "req_xxx",
  "data": {}
}
```

`web-api` 已有接口保留原响应（部分顶层是 `list` + `total`，不包 `data`）。

## 0.4 通用规则

- 金额统一 `string`（decimal，避免精度问题）
- 比例统一 `number`（0–1 小数，前端自行格式化 `%`）
- 时间统一 ISO 8601（`YYYY-MM-DDTHH:mm:ss+08:00`）
- 列表接口统一支持：`page` / `page_size` / `sort_by` / `sort_order`
- 鉴权：`Authorization: Bearer <jwt>`（Lark SSO 颁发）

      "sport": "网球",
      "league": "ATP",
      "event_name": "Djokovic vs Alcaraz",
      "status": "active",
      "opened": true,
      "score": null,
      "times": {
        "open": "2026-05-11T18:00:00+08:00",
        "lock": "2026-05-12T02:00:00+08:00",
        "kickoff": "2026-05-12T02:30:00+08:00",
        "settle": "2026-05-12T05:00:00+08:00"
      },
      "lp_pool_amount": "59388.00",
      "bet_amount_total": "73955.00",
      "max_exposure": "19246.00",
      "settle_pl": null,
      "signal": "orange",
      "market_count": 2,
      "direction_count": 5,
      "yield_ratio": 0.324

**字段说明**

| 字段 | 说明 |
|------|------|
| `opened` | 是否已开盘；`false` 时 `bet_amount_total` / `max_exposure` / `yield_ratio` / `signal` 不计，前端显示「未开盘」 |
| `score` | 终场比分 `{ "home": int, "away": int }`，仅 `status=settled` 非空 |
| `times` | 四个关键时间点：开盘 `open` / 下注截止 `lock` / 开赛 `kickoff` / 开始结算 `settle`（对应 §4.3.1 时间 chip） |
| `bet_amount_total` | 单场下注总额 `sum(markets[*].dirs[*].bet)` |
| `max_exposure` | 调整后单场总计最大敞口 = 各玩法取最坏方向敞口后求和；正=平台风险，负=平台盈利 |
| `settle_pl` | 该盘总盈利/赔付 `sum(各玩法 platformPL)`，仅 `status=settled` 非空，正=平台盈利 |
| `lp_pool_amount` | 当前赛事 LP 底池金额 |
| `yield_ratio` | 收益率 = `abs(max_exposure) / lp_pool_amount`，前端 `>0.5` 红 / `>0.3` 黄 / 其余绿 |
| `signal` | 信号灯 `green` / `yellow` / `orange` / `red`，基于 `max_exposure` 判级 |
| `market_count` / `direction_count` | 玩法数 / 方向总数 |

> **数据来源**：底层赛事 / 盘口数据由 `oddfi-web-api` 提供（`GET /api/v1/detail/fixture/{fixture_id}` `[已有]`），admin 风险评级 / 敞口聚合在其之上封装。
>
> 展开后的「玩法 / 方向明细」字段见 §5.3 赛事详情（对齐看板 PRD §4.3.2）。

## 5.3 赛事详情 [新增]

```
GET /api/v1/admin/events/{event_id}
```

**Path 参数**

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| event_id | integer | 是 | 赛事 ID |

**Response 关键字段**（结构 `markets[] → directions[]`，对齐看板 PRD §4.3.2）

market 级别：

| 字段 | 说明 |
|------|------|
| `market_name` | 玩法名称（如 `胜负` / `让球`） |
| `settle` | 结算条，仅已结算非空：`{ "winners": [...], "payout": "...", "platform_pl": "..." }`（结算方向 / 总赔付 / 平台盈亏，正=平台盈利） |

direction 级别（`markets[].directions[]`）：

| 字段 | 说明 |
|------|------|
| `direction_name` | 投注方向（`dir.label`）；已结算标「✓ 胜出 / 未中 / 走盘」 |
| `bet_amount` | 该方向投注总额 |
| `original_odds` | 开盘赔率 |
| `third_party_odds` | 第三方平台赔率 |
| `third_party_source` | 第三方来源（如 `Bet365` / `Pinnacle`） |
| `odds_diff` | 差值 = 第三方赔率 − 当前赔率（`base` = 已调取新赔率、否则开盘赔率），含百分比 |
| `adjusted_odds` | 新赔率（调整后；未调整=开盘赔率） |
| `original_exposure` | 原风险敞口（调整前） |
| `adjusted_exposure` | 最新风险敞口（调整后；未调整为空） |

# 概述

- **接口规模**：43 个，新增 40 + 已有 3；新增统一前缀 `/api/v1/admin/*`，部署独立 `admin-api` 服务
- **唯一复用**：Withdraw 审批 Tab 全量复用 `web-api` 现有 `/admin/order/pending_orders` / `/admin/order/approve_order` / `/admin/order/order_info`，字段直接按 `oddfi-backend-openapi.yaml` 的 `WithdrawRecord` + `PendingOrderItem` + `WithdrawalAdminItem`
- **手续费结构**：旧 `swap_*` / `lp_fee_*` 字段全部弃用，新版分为 `bet_total`（1%）+ `claim_total`（含 `claim_revenue` + `claim_no_referrer` 2 子项，各 1%）+ `lp_revenue`（20%），合计 = `total_revenue`
- **认证流**：Admin 走独立 Lark SSO（`/api/v1/admin/auth/sso/*`），不复用 Web 端钱包登录；Lark 白名单匹配 + JWT + 写 `audit_log`
- **审批入口三类**：赛事（`signal=red/orange` 自动入审）+ Claim（`claimable_amount > 5000` 自动入审）+ Withdraw（已有审批流），全部经铃铛 `/approval/counts` 聚合红点
- **响应包装**：`admin-api` 统一 `{code, message, data}`；`web-api` 已有接口保留原 `{list, total}` 顶层结构，前端按服务分支适配
- **硬结论**：**Withdraw 审批 Tab 的字段映射要严格对齐 `WithdrawRecord` 真实字段（`order_sn` / `amount` / `to_address` / `status` / `created_at`），不要在 admin 层再造一套新字段名；其他 40 个新增接口才走 `/api/v1/admin/*` 全新设计**
