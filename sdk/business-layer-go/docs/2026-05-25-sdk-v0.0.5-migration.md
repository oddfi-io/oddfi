# oddfi-ODD-SDK v0.0.4 → v0.0.5 迁移指南（按比分结算）

> **日期**：2026-05-25
> **范围**：`contracts-business-layer` 依赖 `github.com/Crypto-Barrett/oddfi-ODD-SDK` 从 `v0.0.4` 升级到 `v0.0.5`
> **读者**：维护本仓库的工程师 / AI Agent。本文给出**对外接口 diff、语义变化、升级步骤、受影响的本层接口、测试方法**，可据此独立完成或复核迁移。

---

## 0. TL;DR

- **v0.0.4→v0.0.5 的全部差异是单个提交** `feat(settlement): support score-based market settlement`。
- 结算模型从「按胜出方一次性结算」改为「**按最终比分分批结算 + 单独 finalize**」（配合合约 AH 让球盘扩盘口 3→10 档）。
- SDK 删除 `SettleMarket`/`SettleMarketCalldata`/`PushRefundMarket`，新增 `SettleMarketBetsByScore(+Calldata)`/`FinalizeMarketSettlement(+Calldata)`/`GetMarketBetIds`/`UpdateOddsCalldata`/`RefundBetsCalldata`。
- 本层（cbl）受影响文件：`admin/methods.go`、`read/client.go`、两个 e2e 测试。升级已在本仓库完成，见 §3–§5。
- **测试网合约（BSC Testnet）已于 2026-05-25 UUPS 升级到该新实现**，代理地址不变（`BettingPool=0xbbc6ef3F665Bf65Cb531172e5f2252155E80cE1F`），e2e 直接可跑。

## 2. 语义变化（务必理解，否则会 revert）

旧模型：`settleMarket(marketId, resultKind, winningOutcome)` 一笔交易给定胜出方即结算完毕。

新模型把「比分结算」拆成两段，并由合约根据比分对每注算 **赢 / 半赢 / 走盘(push) / 输**：

1. **`SettleMarketBetsByScore(marketId, homeScore, awayScore, betIds)`**
   - 单次 `betIds` 长度必须 **1 ≤ n ≤ 50**（合约 `BettingConstants.FINALIZE_BATCH_HARD_CAP`，超出 revert `RefundBatchTooLarge`）。
   - `homeScore`/`awayScore` 必须 ≤ 50（`MAX_SETTLEMENT_SCORE`）。
   - 市场非终态且 `block.timestamp >= matchEndTime`。
   - 大市场需**多次调用**直到处理完全部 betId（合约累计 `processedCount`）。
2. **`FinalizeMarketSettlement(marketId, resultKind)`**
   - `resultKind=0`（Settled）：要求第 1 步已处理**全部** betId（`processedCount == totalBetCount`），否则 revert。
   - `resultKind=1/2`（Refunded/Cancelled）：要求**未**启动过比分结算（progress 必须为空），随后再用 `RefundBets` 逐注退款。
   - **对所有 resultKind 都要求 `block.timestamp >= matchEndTime`**（这点与旧 `pushRefundMarket` 不同——旧的不要求）。

ResultKind 枚举（合约 `SettlementResultKind`）：`0=Settled, 1=Refunded, 2=Cancelled`。

> 关联背景：合约 `AhLine` 让球盘从 3 档扩到 10 档（新增 ±1/4、±3/4、±1.25、平手等）。SDK/本层均以裸 `uint8` 透传 `line`，无需改常量；但**调用方要知道新档位的数值含义**。

### 2.1 标准结算流程（推荐写法）

```go
// 1) 分页取全部 betId，每批 ≤ 50 喂给按比分结算
const batch = 50
for offset := int64(0); ; offset += batch {
    betIDs, err := pool.GetMarketBetIds(ctx, marketID, big.NewInt(offset), big.NewInt(batch))
    if err != nil { return err }
    if len(betIDs) == 0 { break }
    if _, err := pool.SettleMarketBetsByScore(opts, marketID, homeScore, awayScore, betIDs); err != nil {
        return err
    }
    if len(betIDs) < batch { break }
}
// 2) 收尾为 Settled
_, err := pool.FinalizeMarketSettlement(opts, marketID, 0)
```

退款/取消流程：跳过第 1 步，直接 `FinalizeMarketSettlement(opts, marketID, 1 或 2)`，再分批 `RefundBets`。

> ⚠️ 反例：`GetMarketBetIds(..., limit=100)` 后**一次性**把 100 个 betId 丢给 `SettleMarketBetsByScore` —— 当市场注数 >50 时必 revert。务必按 ≤50 分批。

## 4. 受影响的 cbl 接口（本次改动，1:1 镜像 SDK）

### 4.1 `admin/methods.go`

**删除**（含各自 `WithReceipt` 变体与 Request 类型）：

- `SettleMarket` / `SettleMarketRequest`
- `PushRefundMarket` / `PushRefundMarketRequest`

**新增**（每个方法 = 1 笔交易，沿用 `c.submit` calldata 路径 + idempotency + chain_actions）：

```go
const MaxSettleScoreBatch = 50 // 合约 FINALIZE_BATCH_HARD_CAP

type SettleMarketBetsByScoreRequest struct {
    Market         coretypes.MarketKey
    HomeScore      uint16
    AwayScore      uint16
    BetIDs         []coretypes.BetID
    IdempotencyKey string
}
func (c *Client) SettleMarketBetsByScore(ctx, req) (AsyncResult, error)
func (c *Client) SettleMarketBetsByScoreWithReceipt(ctx, req) (ReceiptResult, error)
// 入参校验：len(BetIDs) 必须 ∈ [1,50]，否则 ErrParamInvalid

type FinalizeMarketSettlementRequest struct {
    Market         coretypes.MarketKey
    ResultKind     uint8 // 0=Settled,1=Refunded,2=Cancelled
    IdempotencyKey string
}
func (c *Client) FinalizeMarketSettlement(ctx, req) (AsyncResult, error)
func (c *Client) FinalizeMarketSettlementWithReceipt(ctx, req) (ReceiptResult, error)
// 入参校验：ResultKind 必须 ≤ 2，否则 ErrParamInvalid
```

调用方负责编排「分页取 betId → 按 ≤50 分批 settle → finalize」（本层不做隐式多笔编排，保持「1 方法 = 1 交易」+ 幂等模型）。

### 4.2 `read/client.go`

**新增**只读接口：

```go
// 分页读市场 betId（喂给 SettleMarketBetsByScore 时 limit 建议 ≤ 50）
func (c *Client) GetMarketBetIds(ctx context.Context, key coretypes.MarketKey, offset, limit *big.Int) ([]coretypes.BetID, error)
```

### 4.3 调用方迁移对照

| v0.0.4 旧调用 | v0.0.5 新调用 |
|---|---|
| `admin.SettleMarket{ResultKind:0, WinningOutcome:w}` | `read.GetMarketBetIds` → `admin.SettleMarketBetsByScore{HomeScore,AwayScore,BetIDs}`（按 ≤50 分批）→ `admin.FinalizeMarketSettlement{ResultKind:0}` |
| `admin.SettleMarket{ResultKind:1/2}` | `admin.FinalizeMarketSettlement{ResultKind:1/2}` → `admin.RefundBets` |
| `admin.PushRefundMarket{BetIDs}` | `admin.FinalizeMarketSettlement{ResultKind:1}` → `admin.RefundBets`（注意：现要求 `now >= matchEndTime`） |
