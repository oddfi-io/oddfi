# 升级文档：oddfi-ODD-SDK v0.0.4 → v0.0.5（score-based settlement）

**日期：** 2026-05-25
**影响范围：** `admin/`、`scenario_e2e_test.go`、`refund_methods_e2e_test.go`、`go.mod` / `go.sum`
**业务层发布 tag：** `v0.6.0`

## 1. 背景

`oddfi-ODD-SDK` 在 `v0.0.5` 把 `BettingPool` 的结算从「单笔 `settleMarket(marketID, resultKind, winningOutcome)`」改成了
**基于比分的分批结算**。合约不再读取后端传入的 `winningOutcome`，而是根据最终比分推导每一注的
win / lose / push；并且彻底移除了 `pushRefundMarket`。

本次升级只动了 `admin` 层（调用方），其余 `relay` / `read` / `watcher` 不受影响。

## 2. 依赖变更

```diff
- github.com/Crypto-Barrett/oddfi-ODD-SDK v0.0.4
+ github.com/Crypto-Barrett/oddfi-ODD-SDK v0.0.5
```

通过 `go get github.com/Crypto-Barrett/oddfi-ODD-SDK@v0.0.5 && go mod tidy` 完成。

## 3. SDK 侧的破坏性变更（admin 相关）

| v0.0.4 | v0.0.5 | 说明 |
| --- | --- | --- |
| `SettleMarket(opts, marketID, resultKind, winningOutcome)` | **移除** | 拆成下面的 score-based 三步流程 |
| `SettleMarketCalldata(marketID, resultKind, winningOutcome)` | **移除** | 同上 |
| `PushRefundMarket(opts, marketID, betIDs)` | **移除** | 合约不再暴露 `pushRefundMarket` |
| — | `GetMarketBetIds(ctx, marketID, offset, limit)` ➕ | 分页读取 market 的 betIDs |
| — | `SettleMarketBetsByScore(opts, marketID, homeScore, awayScore, betIDs)` ➕ | 按比分分批结算 |
| — | `FinalizeMarketSettlement(opts, marketID, resultKind)` ➕ | 收口 market 终态 |
| — | `SettleMarketBetsByScoreCalldata` / `FinalizeMarketSettlementCalldata` / `UpdateOddsCalldata` / `RefundBetsCalldata` ➕ | 新增 calldata 编码器 |
| `UpdateOdds` / `RefundBets`（typed wrapper） | 不变 | 签名不变，仍可用 |

合约约束（来自 SDK `docs/architecture/contract_api.md`）：

- `settleMarketBetsByScore`：`block.timestamp >= matchEndTime`，单批 `betIds` 长度 `> 0` 且 `<= FINALIZE_BATCH_HARD_CAP`（≤ 20）。
- `finalizeMarketSettlement`：**同样要求 `block.timestamp >= matchEndTime`**（退款 / 取消路径也一样）。
  - `resultKind=0` Settled：计算 market 级 margin、瀑布并置 `Settled`；
  - `resultKind=1` Refunded：仅标记终态，不遍历 bet，逐笔退款交给 `refundBets`；
  - `resultKind=2` Cancelled：同 1。

> ⚠️ 这是与旧 `PushRefundMarket` 的关键差异：旧方法**不要求** `matchEndTime` 已过；新退款流程必须先等到 `matchEndTime`。

## 4. 业务层 admin API 变更

### 4.1 删除

| 删除项 | 替代方案 |
| --- | --- |
| `admin.SettleMarketRequest` / `SettleMarket` / `SettleMarketWithReceipt` | `SettleMarketBetsByScore` + `FinalizeMarketSettlement`（见下） |
| `admin.PushRefundMarketRequest` / `PushRefundMarket` / `PushRefundMarketWithReceipt` | `FinalizeMarketSettlement(kind=1)` + `RefundBets` |

### 4.2 新增

```go
// 读：分页取 betIDs，驱动 SettleMarketBetsByScore 的分批循环（直接链上读，无 chain_actions 行）
func (c *Client) GetMarketBetIds(ctx, market coretypes.MarketKey, offset, limit *big.Int) ([]coretypes.BetID, error)

// 写：按比分分批结算（SETTLER_ROLE；block.timestamp >= matchEndTime；单批 ≤ 20）
type SettleMarketBetsByScoreRequest struct {
	Market         coretypes.MarketKey
	HomeScore      uint16
	AwayScore      uint16
	BetIDs         []coretypes.BetID
	IdempotencyKey string
}
func (c *Client) SettleMarketBetsByScore(ctx, req) (AsyncResult, error)
func (c *Client) SettleMarketBetsByScoreWithReceipt(ctx, req) (ReceiptResult, error)

// 写：收口 market 终态（ResultKind 0=Settled / 1=Refunded / 2=Cancelled）
type FinalizeMarketSettlementRequest struct {
	Market         coretypes.MarketKey
	ResultKind     uint8
	IdempotencyKey string
}
func (c *Client) FinalizeMarketSettlement(ctx, req) (AsyncResult, error)
func (c *Client) FinalizeMarketSettlementWithReceipt(ctx, req) (ReceiptResult, error)
```

- 三个新写方法都走 `c.submit`（calldata 编码 → 自签自发），与 `OpenMarket` 等保持一致，沿用 chain_actions 幂等语义。
- `GetMarketBetIds` 是 admin 层里唯一的读方法，只为驱动结算分批循环而存在。

### 4.3 不变

- `UpdateOdds` / `RefundBets` 维持现状，继续走 `submitViaSDK`（typed wrapper）。v0.0.5 虽然给它们也补了 `*Calldata`，但本次按「最小改动」未迁移。
- `AddPlatformReserve` / `GrantRole` / `OpenMarket` 不受影响。

## 5. 调用方迁移指南

### 正常结算（原 `SettleMarket(kind=0, winningOutcome=W)`）

```go
// 旧
admin.SettleMarketWithReceipt(ctx, admin.SettleMarketRequest{
    Market: mk, ResultKind: 0, WinningOutcome: W, IdempotencyKey: k,
})

// 新：分页 → 按比分分批结算 → finalize
betIDs, _ := adminCli.GetMarketBetIds(ctx, mk, big.NewInt(0), big.NewInt(100))
if len(betIDs) > 0 {
    adminCli.SettleMarketBetsByScoreWithReceipt(ctx, admin.SettleMarketBetsByScoreRequest{
        Market: mk, HomeScore: home, AwayScore: away, BetIDs: betIDs, IdempotencyKey: k1,
    })
}
adminCli.FinalizeMarketSettlementWithReceipt(ctx, admin.FinalizeMarketSettlementRequest{
    Market: mk, ResultKind: 0, IdempotencyKey: k2,
})
```

- `winningOutcome` 不再传，改为传最终比分 `homeScore` / `awayScore`，由合约推导每注输赢。
- betIDs 超过单页（这里示例 100）时，按 `offset += limit` 翻页，对每页各调一次 `SettleMarketBetsByScore`（注意单批合约上限 ≤ 20，必要时进一步切片），最后再 `FinalizeMarketSettlement` 一次。
- 每个 `SettleMarketBetsByScore` / `FinalizeMarketSettlement` 调用都需要各自独立的 `IdempotencyKey`。

### 退款 / 取消（原 `SettleMarket(kind=1/2)` 或 `PushRefundMarket`）

```go
// 等到 matchEndTime 之后
adminCli.FinalizeMarketSettlementWithReceipt(ctx, admin.FinalizeMarketSettlementRequest{
    Market: mk, ResultKind: 1, IdempotencyKey: k1, // 1=Refunded, 2=Cancelled
})
adminCli.RefundBetsWithReceipt(ctx, admin.RefundBetsRequest{
    Market: mk, BetIDs: ids, RefundAmounts: amts, IdempotencyKey: k2,
})
```
