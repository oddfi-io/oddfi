# ODD-SDK Documentation

`ODD-SDK` 是 oddfi 协议合约的 **公开 Golang SDK**。本目录是站点地图，所有正式文档归入下列子目录之一；任何 Agent 在动手前必须先阅读本文件以及与任务相关的子目录。

## 写作 / 协作约束

- 本目录根下只允许保留本 `README.md`。所有其他文档必须落入下列子目录。
- 新建子目录须先获得用户许可。
- 文档与代码必须双向同步（详见 [`AGENTS.md`](../AGENTS.md) 第 5 节）。
- 所有规范要求以 [`AGENTS.md`](../AGENTS.md) 为准；本文档仅做导航。

## 子目录

| 目录 | 用途 | 何时写入 |
| --- | --- | --- |
| [`architecture/`](./architecture/) | 架构与设计文档：领域模型、公开 API 合约、分层依赖、安全模型、签名 / 交易流水线、可观测性钩子。**应当如此**。 | 架构、API 形状、依赖方向、安全模型变更前 |
| [`development/`](./development/) | 开发文档与实施清单：每项功能 / 重构的背景、范围、API 变更面、测试计划、迁移指引、回滚方案。 | 任何非豁免的功能开发开始前 |
| [`progress/`](./progress/) | 当前真实实现状态，按模块分文件。**实际如此**。 | 任务结束前；占位实现变为可用、范围调整 / 回退 / 延后均须更新 |
| [`testing/`](./testing/) | 测试策略、对抗性测试报告、fuzz 语料、集成 / 端到端记录、安全审计与覆盖率快照。 | 新增测试套件、跑出新审计结论、对抗性测试结束后 |

## 阅读顺序建议

1. [`../AGENTS.md`](../AGENTS.md)：所有 Agent 的强约束规则。
2. `architecture/`：理解领域模型与公开 API 设计意图。
3. `progress/`：确认当前真实状态，避免基于已变更的设计做事。
4. `development/`：当前 / 即将进行的工作清单与实施细节。
5. `testing/`：质量与安全门槛。

## 一致性规则

- **`architecture/` 与代码不一致** → 以代码与 `progress/` 为准，由人工决定是否回写设计文档。
- **新的变更** → 必须先更新 `architecture/` 再改代码。
- 发现文档与代码长期偏离时，必须至少修正一侧并在 PR 描述中点名。
