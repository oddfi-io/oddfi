# odd_agent 生产部署说明

**更新日期：** 2026-05-26
**目标主机：** Ubuntu 24.04  
**部署目录：** `/opt/odd_agent`  
**日志目录：** `/data/logs/odd_agent`  
**监听端口：** `3000`  
**Centrifugo 目录：** `/opt/centrifugo`

## 1. 部署资产

仓库内维护以下部署资产：

- `deploy/scripts/deploy-remote.sh`：远端执行的构建、发布、systemd reload 脚本。
- `deploy/systemd/odd-agent.service`：odd_agent systemd unit。
- `deploy/systemd/centrifugo.service`：Centrifugo Docker systemd unit。
- `deploy/centrifugo/docker-compose.yml`：Centrifugo 容器编排。
- `deploy/centrifugo/config.example.json`：Centrifugo 配置模板，不包含真实密钥。
- `deploy/nginx/lua/jwt_auth.lua`：可选的 Nginx/OpenResty 边缘 JWT 用户 ID 提取脚本。
- `deploy/nginx/odd-agent-auth.example.conf`：可选的 Nginx/OpenResty 用户 ID 提取接入示例。

真实密钥只写入目标机：

- `/opt/odd_agent/shared/odd-agent.yaml`
- `/opt/centrifugo/config.json`

## 2. 运行时配置

`/opt/odd_agent/shared/odd-agent.yaml` 必须保持项目唯一运行时配置口径。生产部署当前要求：

- `server.host: "0.0.0.0"`
- `server.port: 3000`
- `logger.output: "file"`
- `logger.directory: "/data/logs/odd_agent"`
- `db.connection_string_secret_ref: "ODD_AGENT_DATABASE_URL"`
- EC2 测试环境使用 Supabase pooler IPv4 连接串，例如 `aws-1-ap-southeast-1.pooler.supabase.com:6543`；不要使用只解析到 IPv6 且主机无 IPv6 默认路由的 direct DB host。
- `memory.embedding_collection_name: "oddfi"`
- `memory.embedding_dimension: 512`
- `memory.embedding_distance: "cosine"`
- `memory.embedding-llm.model: "text-embedding-v4"`
- `memory.embedding-db.provider: "pinecone"`
- `centrifugo.endpoint: "http://127.0.0.1:18000/api/publish"`
- `tweet_catcher.websocket_endpoint: "wss://monitor-api.tweet-catcher.com/websocket"`
- `user_tag.llm.base_url: "https://api.minimaxi.com/v1"`
- `user_tag.llm.model: "MiniMax-M2.7"`

`local_secrets` 可在该文件内承载部署 secret。日志脱敏字段必须包含 `api_key`、`apiKey`、`authorization`、`password`、`token`。

## 3. 部署流程

从本机同步代码到目标机 release 目录后，在目标机仓库根目录执行：

```bash
bash deploy/scripts/deploy-remote.sh
```

脚本会：

1. 创建 `/opt/odd_agent/releases`、`/data/logs/odd_agent`、`/opt/centrifugo`。
2. 构建 TypeScript。
3. 复制 release 并安装 production dependencies。
4. 将 `/opt/odd_agent/shared/odd-agent.yaml` 覆盖复制为 release 内 `config/odd-agent.yaml` 与 `dist/config/odd-agent.yaml`，并复制 `db/migrations` 到 `dist/db/migrations`。
5. 执行 `node dist/src/bin/migrate.js`，自动创建用户标签表、Chat 会话历史表，并幂等初始化首批 `tags` 目录。
6. 安装/更新 systemd unit。
7. 启动或重启 Centrifugo 与 odd_agent。

注意：从 macOS 打包同步时必须排除 `._*` / `__MACOSX` AppleDouble 元数据文件；否则 `db/migrations/._*.sql` 会被 migration runner 误当成 SQL 执行。

## 4. 验收

基础检查：

```bash
systemctl is-active odd-agent.service
systemctl is-active centrifugo.service
curl -fsS http://127.0.0.1:3000/health
curl -fsS "http://127.0.0.1:3000/internal/tag/tags?page=1&page_size=5"
```

日志检查：

```bash
journalctl -u odd-agent.service -n 200 --no-pager
journalctl -u centrifugo.service -n 100 --no-pager
tail -n 200 /data/logs/odd_agent/odd-agent-$(date -u +%F).log
```

Tweet Catcher 正常启动应看到：

- `tweet_catcher.listener_started`
- `tweet_catcher.connected`
- `tweet_catcher.hello_received`
- `tweet_catcher.identify_sent`
- `tweet_catcher.ready`

收到推文并进入业务链路应看到：

- `tweet_catcher.message_received`
- `tweet_catcher.tweet_received`
- `tag_match.request_started`
- `tag_match.llm_call_completed`
- 命中时出现 `tweet_tag_match.stored`

标签目录初始化成功时，`GET /internal/tag/tags` 的 `total` 应为 58，日志中的 `tag_snapshot.refresh_completed` 应显示 `tag_count:58`。

当前 Chat Agent + Memory 也会随服务启动，健康检查 features 应包含 `foundation`、`memory`、`chat_agent`、`user_tag`。Memory 使用百炼 `text-embedding-v4` 512 维 embedding 与 Pinecone namespace `oddfi`。

如启用 Nginx/OpenResty 边缘 JWT 用户 ID 提取，按 `docs/deployment/nginx-jwt-auth.md` 接入；受保护路由由 Lua 脚本解析 `Authorization` payload 中的 `user_id`，再覆盖写入可信上游 header `x-user-id`。
测试环境 nginx 已安装 `libnginx-mod-http-lua` 与 `lua-cjson`，`/api/*` 转发到 `127.0.0.1:3000` 并启用该 Lua 脚本；`/connection/websocket` 直接转发到 `127.0.0.1:18000/connection/websocket`，不做 nginx 鉴权。

异常关注：

- `tweet_catcher.auth_failed`
- `tweet_catcher.connection_error`
- `tweet_catcher.heartbeat_timeout`
- `foundation.llm.chat_completion_failed`
- `tag_push.publish_failed`
- `FOUNDATION_DB_INIT_FAILED` + `ENETUNREACH`：通常表示目标机解析到 Supabase direct DB IPv6 地址但无 IPv6 出口；切换为 Supabase pooler IPv4 连接串后重跑部署。

## 7. 回滚

查看历史 release：

```bash
ls -1 /opt/odd_agent/releases
```

切换 current 并重启：

```bash
ln -sfn /opt/odd_agent/releases/<release> /opt/odd_agent/current
systemctl restart odd-agent.service
```
