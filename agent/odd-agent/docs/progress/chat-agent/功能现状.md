## 0. DD-134 新增（2026-06-05）

- `POST /api/chat` schema 不变；前端可在 `message` 开头携带 `[intent=match-analysis match_id=NNN persona=... risk=N]` 上下文标记。
- 解析在应用层 `chat-context-marker.ts` 完成：逐字段 zod 校验（枚举 / 数字串 / 0-10 整数），合法字段渲染 `prompts/chat-agent.context.v1.md` 模板后追加到 system 消息尾部；剥离标记后的纯输入才进 `<untrusted_input>` 与 Memory。
- 容错：无标记 / 非 key=value / 全部字段非法 / 剥离后为空 → 按普通对话处理，不报错。
- 会话历史仍保存前端原始 message（含标记）作为 provenance，前端渲染历史时自行剥离。

## 1. 当前目标

新增一个单 Agent Chat 功能：

- `POST /api/chat` SSE 输出。
- `POST /api/create/conversation` 创建当前用户会话。
- `GET /api/conversations` 分页返回当前用户会话列表。
- `GET /api/conversation/detail` 分页返回当前用户会话消息。
- `/api/chat` 保存用户输入和 Agent 最终输出到 PostgreSQL。
- `GET /chat-test` 本地测试页面。
- 回答前 Memory.search。
- 当前输入放在 prompt 最后。
- Memory.search 完成后立即异步 Memory.write。
- system prompt 拒绝非运动、赛事、交易相关请求。
- Chat LLM 注册通用 `web_search` tool，用于任意互联网搜索；工具自身不做运动、赛事、交易范围控制。

## 2. 已确认约束

- 不恢复旧多 Agent / Chat / Workflow 文档。
- 不新增分散配置文件；仍使用 `config/odd-agent.yaml`。
- 真实 MiniMax、Pinecone、百炼 key 不写入仓库，只通过 secret ref 解析。
- Memory 事实源继续使用 Embedding DB；本轮按 Pinecone provider 接入。
- 不使用 OpenAI 自带 Web Search；当前实现使用官方 Brave Search MCP server 作为当前模型的 function tool。
- 会话历史新增 PostgreSQL 表 `conversaction` / `conversaction_detail`，按 `x-user-id` 隔离；表名沿用当前需求拼写。

## 3. 已完成

- 新增 `POST /api/chat` SSE 接口。
- 新增 `GET /chat-test` 本地测试页面，HTML 位于 `test/chat-agent/chat-test.html`，内置记忆写入、记忆召回、阻拦验证和联网搜索验证场景。
- `/chat-test` 页面打开时会自动调用 `POST /api/create/conversation` 创建测试会话，并把返回的 `conversation_id` 用于后续 `/api/chat`。
- Chat Agent system prompt 已文件化到 `prompts/chat-agent.system.v1.md`。
- Chat Agent messages 现在包含 `<runtime_context>`，用于给模型提供当前 UTC 日期，避免相对日期被猜错。
- 回答前调用 Memory.search，且 Memory prompt 位于当前用户输入之前。
- 当前用户输入使用 `<untrusted_input>` 包裹并放在最后。
- Memory.search 完成后立即异步调用 Memory.write；失败只记录日志，不阻塞 LLM streaming。
- 配置新增 `chatllm`，Memory 参数、Memory LLM、embedding LLM、embedding DB 已收敛到顶层 `memory` 下，真实 key 仍只走 secret ref。
- 组合根使用 MiniMax Chat LLM、百炼 embedding、Pinecone provider 初始化 Memory v3。
- 新增顶层 `tools` 配置，包含 `max_tool_calls` 和 `brave-search`。
- 新增 `src/application/tools/brave-search-mcp.ts`，封装通用 `web_search` function tool 和 Brave MCP `brave_web_search` 调用。
- Chat Agent prompt 现在包含 `<registered_tools>`，并在 streaming Chat Completions 请求中传入 `tools` 和 `tool_choice:"auto"`。
- Chat Agent 支持 streaming tool loop：content delta 立即 SSE 输出；tool_call delta 在本轮 stream 结束后拼接、执行工具、回填结果，再继续下一轮 streaming。
- 由模型决定何时结束工具调用；代码只限制 `tools.max_tool_calls`，达到上限后不再传 tools，让模型基于已有信息收束回答。
- `<think>...</think>` reasoning 片段不再过滤，会按模型输出原样显示到测试页面。
- Chat 运行时会按配置拉起官方 Brave Search MCP server，并在应用关闭时关闭 MCP 子进程。
- 会话持久化设计已同步到 `docs/architecture/chat-agent/架构设计.md` 与 `docs/development/chat-agent/功能设计.md`。
- 新增 migration `db/migrations/0006_chat_conversations.sql`，创建 `conversaction` 和 `conversaction_detail`。
- 新增 `PostgresConversationRepository`，支持创建会话、确保会话归属、写入消息、分页列出会话和分页读取详情。
- HTTP 新增 `POST /api/create/conversation`、`GET /api/conversations`、`GET /api/conversation/detail`。
- `/api/chat` 要求传入已存在且归属当前用户的 `conversation_id`；不存在、缺失或跨用户时直接报错，不自动创建会话。接口会在 SSE 前写入用户消息，并在 `done` 前写入由 token 累计得到的 Agent 最终消息。
