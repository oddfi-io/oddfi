# Foundation 功能现状

**更新日期：** 2026-05-22
**状态：** Foundation 组件保持独立可用；Embedding DB 已支持多 provider；Memory 已切换为 provider 注入的 Embedding DB 事实源

## 2026-05-26 Nginx JWT 边缘用户 ID 提取脚本

- 新增 `deploy/nginx/lua/jwt_auth.lua`，作为部署边缘的 OpenResty Lua 用户 ID 提取脚本；它不进入 Foundation 组件初始化链路，也不读取 `config/odd-agent.yaml`。
- 脚本只解析 Bearer JWT payload 中的 `user_id`，不验签、不查 Redis、不校验 `exp/nbf/iat`，通过后覆盖写入可信上游 header `x-user-id`。
- 若 payload 中有字符串 `address` / `jti`，脚本会同步透传为 `x-user-address` / `x-token-jti`；解析成功后清理原始 `Authorization` header。
- 脚本已放行 `OPTIONS` 预检请求；HTTP 服务 CORS 允许 `authorization` header，避免浏览器通过 nginx 调用 `/api/*` 时预检失败。
- 新增 `scripts/verify-nginx-jwt-auth.ts` 用于本地离线验证 payload 解析与上游 header 映射；生产接入说明见 `docs/deployment/nginx-jwt-auth.md`。

## Embedding DB 当前状态

- API 已强制 `userId` 作为 upsert/search/delete 的一等参数，filter 只表达业务维度。
- Embedding DB 已拆为组件门面 + provider 接口：门面保留公共校验、日志和生命周期，具体实现由初始化 deps 注入，provider 私有配置留在各自 `embedding-db-provider-*.ts`。
- Qdrant provider 已实现 init/upsert/search/getById/list/delete/healthCheck，向量数据不再默认写入 PostgreSQL。
- Qdrant point id 由 `userId + id` 稳定映射，原始业务 id、content、metadata 保存在 payload。
- pgvector 保留为兼容 provider，仍支持 `(user_id, id)` 复合主键和原生 vector operator 检索。
- Milvus / Pinecone / Chroma 已提供独立 HTTP provider 类，provider 私有配置留在各自构造参数中；Provider Matrix 已覆盖真实连通和大样本场景。
- 写入会把 `userId` 同步写入 metadata，便于审计和兼容读取。
- filter / metadata 会拒绝 `undefined` 值，content / metadata 有最大字节数限制。
- 新增 `getById(userId,id)` 和 `list(userId,filter,page,pageSize)`，支持 Memory 不依赖 PostgreSQL 主表直接做事实读取和 metadata 列表查询。
- 新增 `deleteByUser(userId)`，delete 操作输出 info 级审计日志并记录 `user_id_hash`。
- memory provider 仅用于单元测试；healthCheck 返回 `degraded` 并标明 in-memory backing。

## Memory 当前状态

- Memory 已删除旧 L1/L2/L3/L4、结构化记忆 `update/queryStructureMemory` 和用户标签格式化方案，当前只保留长期语义记忆 SDK。
- 对外接口为 `init/write/search/list/delete`，所有方法按 `userId` 隔离；`write()` 强制 `conversationId`，内部生成 `sourceMessageId`。
- `CandidateExtractor` 和 `MemoryDiff` 通过 prompt 资产调用 LLM，prompt 位于 `prompts/memory.*.v1.md`；外部 message 用 `<untrusted_input>` 包裹。
- `semantic_key` 由 `memory.semantic_keys` 配置硬约束；`event` 类型永远只 ADD，不参与 UPDATE 或 DELETE。
- Memory 不再使用 PostgreSQL `memories` / `memory_events` 主表；长期记忆事实源为 Foundation Embedding DB。
- Memory 写入把文本放入 Embedding DB `content`，结构化字段放入 metadata，active 由 `metadata.active` 表达；给业务 LLM 的上下文可用 `formatMemorySearchContext()` 渲染，不暴露内部 id 或 score。
- Memory 的向量生成已改为必需依赖 `OpenAiLlmEmbeddingComponent.embeddings`，写入、更新、删除和 search 都通过 `llmEmbedding.embedText(..., { dimensions: memory.embedding_dimension })` 生成真实向量，不再保留可选 `embedText` 注入或本地 hash fallback。
- Memory 结构化 LLM 输出新增真实 provider 容错：candidate extraction 和 diff 使用 OpenAI `response_format=json_schema` 后，还会用 zod 做最终 schema 校验；对 MiniMax 真实长跑中出现的空输出、非法 JSON、schema 枚举不匹配会在同 prompt 下最多重试 5 次，仍失败才抛 Memory AppError。
- Pinecone provider 新增 `timeoutMs`、`maxRetries`、`retryDelayMs` provider 私有配置；真实 100 轮回归曾暴露 Pinecone data-plane 偶发 TCP connect timeout，现由 provider 层做可重试网络错误归一化和线性退避。
- Pinecone provider 已收敛 namespace 语义：不再接受 provider 私有 `namespace` 字段，统一使用 `EmbeddingDbConfig.collectionName` 作为 Pinecone namespace；`collectionName` 在 pgvector/Qdrant/Chroma/Milvus/Pinecone 中都必须映射到真实存储分区。
