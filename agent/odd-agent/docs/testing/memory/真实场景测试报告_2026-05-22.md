## 2. 回归过程

- 第一次按旧脚本 `timeoutMs=60000` 执行，在 MemoryDiff 阶段触发 MiniMax 请求 `AbortError`，失败类型为外部 LLM 请求超时。
- 脚本改为支持 `MINIMAX_TIMEOUT_MS`，默认提升到 `180000ms`。
- Embedding DB provider 从 pgvector/memory 切换为 provider 注入口径；Qdrant 和 Pinecone 都由 `MemoryComponent.init()` 内部初始化 Embedding DB。
- Pinecone 场景使用运行时 API key 创建临时 serverless index，按 Ollama embedding 实际维度 `384` 建索引，结束后清理临时 index。
- 脚本会写入 `tmp/memory-real/latest.json` 和 `tmp/memory-real/summary-for-table.json` 的干净 JSON 报告，避免只依赖 stdout。

## 5. 结论

- 当前 Qdrant 与 Pinecone 口径下，Memory 的 ADD / UPDATE / search / list / soft delete 通过真实 MiniMax、真实 Ollama embedding 和真实 provider-backed Embedding DB 回归。
- 回归链路没有使用 Memory PostgreSQL 主表，也没有把 EmbeddingDb provider 指向 pgvector。
- 删除链路按 metadata 标记完成：`delete()` 默认通过 `upsert(active=false, deletedAt=...)` 软删除；默认 query/list 带 `active=true`，不会返回已删除记录。
- 外部 MiniMax 响应可能超过 60 秒，真实回归脚本应保留可配置超时。

本轮真实验证暴露并修复的问题：

- Pinecone data-plane 偶发 TCP connect timeout：`PineconeEmbeddingDbProvider` 增加 provider 私有 `timeoutMs`、`maxRetries`、`retryDelayMs`，网络失败归一为可重试 Foundation 错误。
- 每轮额外 `list()` 会放大 Pinecone metadata fetch 压力：真实脚本保留每轮 `write + search`，最终再集中做 `list/delete/query/cross-user` 验收。
- MiniMax 结构化输出长跑中出现长尾超时、空 content、非法 JSON 和 schema 枚举不匹配：Memory 结构化调用层对空输出、非法 JSON、zod schema 不匹配进行同 prompt 有限重试，仍失败才抛 Memory AppError。
- 真实脚本已改为百炼 `text-embedding-v4` 生成 512 维向量，不再使用 Ollama embedding 或旧可选 `embedText` 注入。
