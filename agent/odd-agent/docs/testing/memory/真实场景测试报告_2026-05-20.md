## 3. Write / Update 明细

| 轮次 | 用户输入 | LLM 调用 | Diff 动作 | 存储结果 |
|---|---|---|---|---|
| T1 | 请记住：我喜欢简洁的中文回答，同时我主要写 Rust。 | candidate_extract + 2 次 memory_diff | `ADD`、`ADD` | 存入“简洁中文回答偏好”和“主要写 Rust” |
| T2 | 我现在已经不用 Java 了，主要写 Rust。 | candidate_extract + memory_diff | `ADD` | 存入“主要写 Rust，不再使用 Java” |
| T3 | 昨天我参加了 PostgreSQL pgvector 的线上工作坊。 | candidate_extract | `ADD` | event 类型，按规则直接 ADD |
| T4 | 我正在做 odd_agent 的 Memory v3 组件测试。 | candidate_extract + memory_diff | `ADD` | 存入当前正在测试 Memory v3 |
| T5 | 更新一下：我现在主要写 Go，不再主要写 Rust。 | candidate_extract + memory_diff | `UPDATE` | 更新原 `current_state.primary_language` 记忆为 Go |

## 4. UPDATE 真实路径

| 项 | 内容 |
|---|---|
| 触发输入 | `更新一下：我现在主要写 Go，不再主要写 Rust。` |
| CandidateExtractor 输出 | `text=我现在主要写 Go，不再主要写 Rust`，`type=current_state`，`semantic_key=current_state.primary_language`，`confidence=0.95` |
| MemoryDiff 输出 | `action=UPDATE`，`target_id=mem_0913d4ca-7dc7-4d5e-a375-b8c1e2773ebd` |
| 更新原因 | candidate 和旧 memory 都是 `current_state.primary_language`，描述同一个“主要编程语言”槽位，新事实把 Rust 更新为 Go |
| 事件表记录 | `action=UPDATE`，`old_text=主要写 Rust，不再使用 Java`，`new_text=我现在主要写 Go，不再主要写 Rust` |
| 主表结果 | 原 memory 行被更新，`text` 变为 Go，`deleted_at=null` |

| 场景 | 输入 | 日志/返回 | 结果 |

## 8. 结论

- Memory v3 在真实 MiniMax、真实 pgvector、真实 Ollama embedding 下通过正向和反向场景。
- `write()` 能真实触发 ADD 和 UPDATE。
- `event` 保持 ADD-only。
- `search()` 没有跨用户泄漏，非法 semantic key 过滤为空。
- `delete()` 拒绝跨用户删除，并能对当前用户 memory 软删除且同步删除向量索引。
