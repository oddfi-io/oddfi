# Memory 组件功能文档

**状态：** v3 长期语义记忆 SDK 已切换为 Embedding DB 事实源
**更新日期：** 2026-05-22

## 1. 当前口径

Memory 是独立长期语义记忆 SDK，旧 L1/L2/L3/L4、结构化记忆 `update/queryStructureMemory`、用户标签格式化和 Redis compact 方案全部删除，不再兼容。

当前实现口径：

- Memory 和 DB、Embedding DB、LLM、LLM Embedding、Logger 同级，但 Memory 不再依赖 PostgreSQL。
- Embedding DB 是 Memory 的事实源和语义检索存储：`content` 保存 memory 文本，`metadata` 保存结构化字段。
- Memory 初始化必须传入 Embedding DB provider 和已初始化的 LLM Embedding 组件；Memory 会在 `init()` 内部用该 provider 初始化 Embedding DB。
- Memory 不感知 Agent，不要求 `agent_id`。
- `conversationId` 由调用方强制传入，表示 memory 来源会话。
- `sourceMessageId` 由 `MemoryComponent.write()` 每次内部生成，表示本次 message。
- `event` 类型 memory 永远只 ADD，不参与 UPDATE 或 DELETE。
- active 由 Embedding DB metadata 中的 `active=true` 表达；soft delete 会把 `active=false` 并写入 `deletedAt`。

## 2. 初始化依赖

```ts
type MemoryInitDeps = {
  readonly embeddingDb: Pick<
    FoundationEmbeddingDb,
    "init" | "healthCheck" | "upsert" | "search" | "getById" | "list" | "deleteByFilter"
  >;
  readonly embeddingDbProvider: EmbeddingDbProvider;
  readonly secretProvider?: SecretProvider;
  readonly llm: OpenAiChatCompletionClient;
  readonly llmEmbedding: OpenAiEmbeddingClient;
  readonly logger: LoggerComponent;
};
```

Memory 内部不创建基础设施实例，但会使用 `embeddingDbProvider` 初始化调用方传入的 Embedding DB 实例。`secretProvider` 用于 Pinecone/Qdrant/Milvus 等需要凭据的 provider；`llmEmbedding` 必须由组合根通过 `OpenAiLlmEmbeddingComponent` 初始化后传入，Memory 的写入和检索都通过它生成真实向量。

LLM 与 embedding 分离传入：`llm` 只用于 candidate extraction 和 diff；`llmEmbedding` 只用于把 memory 文本或 query 转成向量。禁止再传可选 `embedText` 函数或本地 hash fallback；向量维度必须由 `memory.embedding_dimension` 统一传给 `llmEmbedding.embedText(text,{ dimensions })`。

## 3. 对外接口

```ts
class MemoryComponent {
  init(config: MemoryConfig, deps: MemoryInitDeps): Promise<void>;
  write(command: MemoryWriteCommand): Promise<readonly DiffResult[]>;
  search(command: MemorySearchCommand): Promise<readonly MemorySearchResult[]>;
  list(command: MemoryListCommand): Promise<readonly Memory[]>;
  delete(command: MemoryDeleteCommand): Promise<void>;
}
```

`delete()` 必须带 `userId`，禁止只按 `memoryId` 删除。

## 4. 存储

Memory 不再自带 PostgreSQL 表，不再使用 `memories` / `memory_events` migration。长期记忆存储在 Foundation Embedding DB collection 中。

每条记录：

- `id`：memoryId。
- `userId`：Embedding DB 一等隔离键。
- `content`：memory 文本。
- `vector`：由 `llmEmbedding.embedText(content, { dimensions: embeddingDimension })` 生成。
- `metadata`：`memoryComponent`、`memoryId`、`active`、`type`、`semanticKey`、`confidence`、`importance`、`conversationId`、`sourceMessageId`、`createdAt`、`updatedAt`、`deletedAt?`、`tags?` 等。

删除语义：

- 默认 `delete()` 是软删除，不物理删除向量记录。
- 软删除会用同一 `memoryId` 执行 `EmbeddingDb.upsert()`，只把 metadata 更新为 `active=false` 并写入 `deletedAt`。
- `search()` 和默认 `list()` 都带 `active=true` metadata filter，因此查询结果不会包含已软删除记录。

## 5. 内部流程说明

| 角色 | 为什么需要 | 当前实现 |
|---|---|---|
| CandidateExtractor | 把自然语言 message 拆成结构化 durable facts，过滤一次性闲聊、敏感信息和不稳定内容。 | `#extractCandidates()` 调用 LLM structured output，输出 `MemoryCandidate[]`。 |
| MemoryRetriever | 给 diff 提供同用户、active、相关的旧 memory，避免重复 ADD、漏掉 UPDATE 或让 LLM 编造 target。 | `#retrieveRelated()` 做 Embedding DB `list` semanticKey 精确召回 + Embedding DB `search` 语义召回。 |
| MemoryDiff | 比较一个 candidate 和 related memories，决定 ADD/UPDATE/DELETE/NOOP。 | `#diffCandidate()` 对 event 直接 ADD；其他类型调用 LLM diff prompt。 |
| Validator | LLM 输出不能直接落库，需要本地规则兜底。 | `validateCandidate()` 和 `validateDiff()` 校验 confidence、semanticKey、targetId、event 规则。 |
| CommitHandler | 把已验证动作写入 Embedding DB。 | `#commitDiff()` 处理 ADD/UPDATE/DELETE，`#commitNoop()` 只返回 NOOP 结果不写存储。 |

结构化 LLM 调用说明：

- Candidate extraction 和 diff 都使用 OpenAI Chat Completions `response_format=json_schema`。
- Memory 仍会从 provider 返回的 message content 中抽取 JSON，再用 zod 做最终 schema 校验。
- 真实 MiniMax 长跑中可能出现空 content、Markdown fence、非法 JSON、schema 枚举不匹配或长尾超时；Memory 对空输出、非法 JSON 和 zod schema 不匹配做最多 5 次同 prompt 重试，仍失败时抛 Memory AppError。
- 每次请求显式传 `max_tokens`，candidate extraction 当前为 `1600`，diff 当前为 `1200`，避免结构化输出被远端无限拉长。

## 7. 验收摘要

- 新事实 ADD。
- 同 semantic key 的新版本 UPDATE。
- 重复事实 NOOP。
- 明确否定且无替代事实时 DELETE soft delete。
- `event` 永远只 ADD。
- 非法 semanticKey、低 confidence、targetId 不在召回集时 NOOP。
- `search/list/delete` 全部按 `userId` 隔离。
- Memory 不再依赖 PostgreSQL 主表；PostgreSQL 只作为 pgvector provider 的可选底层宿主或 user-tag 的业务库。
