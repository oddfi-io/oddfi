# 用户标签表设计

**状态：** 已落地首版 migration、record schema、repository 与幂等 tags seed
**更新日期：** 2026-05-22
**范围：** 用户选择标签能力的数据表设计；首版已接入 `db/migrations/0002_user_tags.sql` 与 `PostgresTagRepository`，tags 目录随同一 migration 自动初始化。

## 设计目标

用户标签是独立的用户偏好能力。第一阶段只设计 PostgreSQL 表，用于后续支持用户选择关注的国家、球员等标签，并供画像、推送匹配和 Agent 上下文读取。

设计原则：

- 标签目录必须可扩展，不能把国家 / 球员写死成代码枚举。
- 标签目录与用户选择关系分离。
- 用户选择归属 `user_id`，不绑定 `agent_id`。
- 所有用户标签查询必须带 `user_id`，禁止跨用户读取。
- 第一版只保留用户选择所必需的字段；多语言展示名使用明确的 `lang_metadata` JSON，不放泛化 metadata。
- 本功能禁止数据库外键关联；跨表一致性由应用服务在写入时校验，查询时通过普通 `tag_id` 做显式关联。
- 本文描述当前已落地的 migration 设计。

## 表一：`tags`

用途：保存系统可展示、可选择、可匹配的标签目录。首批标签包含国家和球员，后续可扩展到 league、team、market、source 等 category。

建议字段：

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGSERIAL | PK | 数据库自增主键 |
| `category` | VARCHAR(30) | NOT NULL | 首批使用 `country` / `player`；后续允许扩展 |
| `lang_metadata` | JSONB | NOT NULL | 多语言展示名，例如 `{"en":"United States"}`、`{"en":"Côte d'Ivoire"}` |
| `sort_order` | INTEGER | NOT NULL DEFAULT 0 | 前端展示排序 |
| `deleted_at` | TIMESTAMPTZ | NULL | 标签下架/软删除时间；NULL 表示可用 |
| `created_at` | TIMESTAMPTZ | NOT NULL | UTC |
| `updated_at` | TIMESTAMPTZ | NOT NULL | UTC |

建议约束和索引：

- `CHECK (category <> '')`
- `CHECK (jsonb_typeof(lang_metadata) = 'object')`
- `CHECK (lang_metadata ? 'en')`
- `INDEX tags_category_deleted_sort_idx ON tags (category, deleted_at, sort_order, id)`

暂不设计字段：

- `slug`：当前没有对外稳定 URL、导入 key 或外部引用需求。
- `name`：展示名直接从 `lang_metadata` 按语言读取，首版至少包含 `en`。
- `normalized_name`：当前没有搜索/模糊匹配需求，先不为未来搜索做提前设计。
- `aliases`：首版只是用户从固定列表选择，不做同义词/别名匹配。
- `metadata`：暂时没有已确定字段，避免把未建模数据塞进泛化 JSON。

## 表二：`user_tags`

用途：保存用户主动选择的标签。它是用户级长期偏好，不绑定 `agent_id`；后续如果某个 Agent 需要自己的标签视图，应通过 read model 或额外 scope 扩展，不在 v1 混入本表。

建议字段：

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | BIGSERIAL | PK | 数据库自增主键 |
| `user_id` | VARCHAR(100) | NOT NULL | 可信上游用户 ID |
| `tag_id` | BIGINT | NOT NULL | 被选择的标签 ID；不建数据库外键 |
| `desc` | TEXT | NOT NULL DEFAULT `''` | 用户标签关系描述，默认空字符串 |
| `deleted_at` | TIMESTAMPTZ | NULL | 用户取消选择时间；NULL 表示当前选中 |
| `created_at` | TIMESTAMPTZ | NOT NULL | UTC；表示用户首次选择时间 |
| `updated_at` | TIMESTAMPTZ | NOT NULL | UTC |

建议约束和索引：

- `UNIQUE (user_id, tag_id)`，保证同一用户同一标签只有一条当前事实记录。
- `INDEX user_tags_user_deleted_idx ON user_tags (user_id, deleted_at, updated_at DESC)`
- `INDEX user_tags_tag_deleted_idx ON user_tags (tag_id, deleted_at)`
- 不创建 `FOREIGN KEY (tag_id) REFERENCES tags(id)`。

## 删除策略

- 用户取消选择默认软删除：写 `deleted_at`。
- 重新选择同一个标签时，复用原 `user_tags` 记录并清空 `deleted_at`。
- Permanent Delete 用户数据时再物理删除该用户的 `user_tags`。
- `tags` 目录不因用户删除而删除；标签下架时写 `deleted_at`。

## Migration 落地要求

首版已落地：

- `src/models/db/persistence-model.ts` 已增加 `tagRecordSchema` 与 `userTagRecordSchema`。
- `db/migrations/0002_user_tags.sql` 已增加幂等建表 SQL 与首批 `tags` seed。
- `src/infrastructure/tags/postgres-tag-repository.ts` 已实现首版 repository。

seed 规则：

- seed 必须写成幂等插入。由于首版不设计 `slug/name` 唯一键，`0002_user_tags.sql` 按 `category + lang_metadata->>'en'` 判断是否已存在，再插入或更新 `lang_metadata`、`sort_order`、`deleted_at`、`updated_at`。
- `user_tags` 的所有 repository 查询必须强制传入 `user_id`。
- 写入 `user_tags` 前，应用服务必须校验 `tag_id` 存在且对应 `tags.deleted_at IS NULL`；数据库层不使用外键。
- 用户选择页默认只返回 `tags.deleted_at IS NULL` 的标签。
