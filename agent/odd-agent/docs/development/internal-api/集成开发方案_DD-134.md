# DD-134 集成开发方案（AI Agent 侧实现细节）

> 架构口径见 `docs/architecture/internal-api/架构设计.md`。本文记录实现层细节与测试矩阵。

## 任务 1 · X-Service-Token middleware

实现位置：`src/interface/http/server.ts` `buildServer` 内 onRequest hook。

- `BuildServerOptions` 新增 `internalServiceToken?: string`。
- hook 逻辑：`req.url` 不以 `/internal/` 开头（且不等于裸 `/internal`）→ 放行；`OPTIONS` 预检放行落到统一 204 handler；`internalServiceToken === undefined` → 500 `{ error: "service_token_misconfigured" }`；header `x-service-token` 缺失或经 `timingSafeEqual` 常量时间对比不等 → 401 `{ error: "invalid_service_token" }`。
- 组合根 `src/init.ts`：通过 `secretProvider.getSecret(appConfig.internalAuth.serviceTokenSecretRef)` 启动期解析，缺失即抛错 fail-fast。
- 配置 schema：`src/models/config/odd-agent-config-model.ts` 新增 `internalAuthConfigSchema`。

测试（`server.test.ts`）：

| 用例 | 期望 |
|---|---|
| 不带 token 调 `/internal/tag/tags` | 401 invalid_service_token |
| 错误 token | 401 |
| 正确 token | 现有行为不变 |
| buildServer 未配置 token 时调 `/internal/*` | 500 service_token_misconfigured |
| `/api/*` 与 `/health` 不带 token | 不受影响 |
| 现有 internal 用例 | 注入正确 token 后全部保持通过 |

## 任务 2 · GET /internal/memory/list

实现位置：`src/interface/http/server.ts` 新增 route；`BuildServerOptions` 新增 `memoryComponent?: Pick<MemoryComponent, "list">`。

- query zod schema（`src/models/http/memory-dto-model.ts`）：`limit` coerce int，默认 20，`1 ≤ limit ≤ 100`（超限 zod 报错 → 400）；`cursor` 可选非空字符串（**不透明**，当前格式 `${createdAt}|${id}`，兼容旧纯 createdAt）。
- 流程：校验 `x-user-id` →（middleware 已校验 token）→ `memory.list({ userId, page: 1, pageSize: maxPageSize, orderBy: "createdAt" })` → 按 `(createdAt, id)` 复合键倒序 → cursor 过滤（复合键严格小于）→ 取 limit 条 → 映射 5 字段。
- `nextCursor`：过滤后仍有剩余 → 最后一条的 `${createdAt}|${id}`；否则 null。同一毫秒多条记录不丢不重。
- Memory.list 抛错 → 500 `{ error: "memory_list_failed" }`；memory 未装配 → 503 `{ error: "memory_unavailable" }`（主后端 client 需把 4xx/5xx 一律按失败打点处理）。

测试：分页/排序/cursor 续页/同 createdAt 多条复合游标遍历不丢不重/limit 越界 400/缺 x-user-id 400/memory 未配置 503/下游失败 500。

## 任务 3 · Chat 上下文标记

实现位置：`src/application/chat/chat-context-marker.ts`（新文件，纯函数）+ `chat-agent-service.ts` 接入 + `prompts/chat-agent.context.v1.md` 模板。

- 正则 `^\[([^\]\n]+)\]\s*` 抽取首个方括号块（`\s*` 已覆盖 CRLF / 全角空格）；按空白拆 `key=value` 对，重复 key 取最后一个（last-wins）。
- zod schema：`intent: "match-analysis"`、`match_id: /^\d{1,20}$/`、`persona: enum`、`risk: 0-10 int`；逐字段独立校验，非法字段丢弃不影响其他字段。
- 全部字段非法或无标记 → 返回 `{ context: undefined, message: 原文 }`。
- ChatAgentService：`streamChat` 入口解析；`cleanMessage` 用于 memory search/write 与 `<untrusted_input>`；context 渲染模板后 append 到 system 消息尾部。
- 模板占位符只接受 zod 校验后字段（满足「system 消息只允许 schema 校验过的安全字段插值」红线）。

测试：完整标记 / 部分字段 / 未知字段忽略 / 非法值丢弃 / 无标记 / 标记后空消息（视为无效输入，保留原文）/ 注入尝试（value 含 `<` `>` 等被 enum/正则拒绝）。

## 任务 4 · batch-create 幂等性

串行幂等现状已满足（`PostgresTagRepository.createMany`：`findByCategoryAndEnglishName` 命中 → `updateTag(restore: true)` 返回现有 id）。review 发现并发竞态缺口（check-then-insert 无 DB unique 兜底，违反项目红线），已补足：

- migration `db/migrations/0007_tags_category_en_unique.sql`：先软删去重既有重复活跃行（保留最小 id），再建 partial unique index `tags_category_en_active_unique ON tags (category, (lang_metadata->>'en')) WHERE deleted_at IS NULL`；回滚方案见 migration 注释。
- `createMany` INSERT 改为 `ON CONFLICT ... DO NOTHING`，冲突时回查返回赢家的同一 tag_id。

补契约测试：

- 重复 create 同 category+en → 返回同一 id，不报错。
- 缺 `lang_metadata.en` → 进 failed，不阻断同批其他项。
- 软删除后重复 create → 恢复并返回原 id。
