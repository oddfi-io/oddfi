# Internal API 集成架构设计（DD-134 AI Agent 侧）

> 来源：`oddfi-frontend/.progress/designs/DD-134-ai-agent-user-profile-sync-protocol/handoff/ai-agent-impl.md`。
> 本文档定义 AI Agent 服务对主后端 (web-api) 的 internal API 安全模型与集成边界。

## 1. 背景与边界

OddFi 主后端（api.oddfi.io，Go）作为前端与本服务之间的中转层：

```
前端 (JWT) → 主后端 → AI Agent :3000
                      X-Service-Token + X-User-Id (string)
```

- 本服务不做用户鉴权；`/api/*` 用户身份只信可信上游 header `x-user-id`（既有口径不变）。
- `/internal/*` 仅允许主后端服务间调用，**必须**携带 `X-Service-Token` 静态密钥。
- 同步语义 fire-and-forget：主后端失败不 retry，本服务不需要补偿逻辑。

## 2. 安全模型：X-Service-Token middleware

| 项 | 决策 |
|---|---|
| 覆盖范围 | 所有 `/internal/*` 路由（onRequest hook，前缀匹配） |
| 校验方式 | 静态字符串对比（不做 HMAC 时间戳，保持简单） |
| token 未配置 | 请求期返回 500 `{ error: "service_token_misconfigured" }`；同时组合根启动时 fail-fast（双保险） |
| token 错误/缺失 | 401 `{ error: "invalid_service_token" }` |
| `/api/*` | 不受影响 |
| 密钥来源 | 配置 `internal_auth.service_token_secret_ref` → EnvSecretProvider（dev 用 `local_secrets` / env var `SERVICE_TOKEN`；生产由运维从 AWS SSM 注入同名 env） |
| 轮换 | 90 天周期，由运维侧驱动；本服务重启加载新值 |

错误响应 shape 采用 handoff 跨团队契约（`{ error: string }`），主后端只判断状态码。

## 3. Memory HTTP wrapper

新增 `GET /internal/memory/list?limit=20&cursor=<createdAt ISO>`（Header：`X-Service-Token` + `X-User-Id`）。

- 包装 Foundation `Memory.list`；SDK `list` 新增 `orderBy: "createdAt" | "updatedAt"`（默认 updatedAt），wrapper 以 `orderBy: "createdAt"` 请求，保证截断窗口与对外分页排序键一致。
- 输出简化 5 字段：`id / text / type / importance / createdAt`，按 `(createdAt, id)` 复合键倒序——同一毫秒多条记录时仍是稳定全序。
- cursor 语义：**对调用方不透明的字符串**，当前格式 `${createdAt}|${id}`；服务端取复合键严格小于 cursor 的下一页，**不丢不重**。兼容旧的纯 `createdAt` cursor（按严格小于过滤）。调用方（主后端 Go client / 前端）必须原样透传，不要解析其结构。
- limit 默认 20、max 100，超限 400。
- 错误码：`400 x_user_id_required / invalid_query`、`503 memory_unavailable`（memory 未装配）、`500 memory_list_failed`（下游失败，已打结构化错误日志）。
- 本期不做 type 过滤、不做 summary endpoint、不暴露删除/编辑。
- 已知限制：Memory SDK 是 page/pageSize 分页 + Pinecone metadata list，wrapper 单次最多读取 `memory.max_page_size`（当前 100）条（按 createdAt 倒序窗口）再做 cursor 过滤；单用户活跃记忆超过该量级时更早的记录翻不到（深分页截断）。需联调期评估世界杯单用户记忆量级，必要时调大 `memory.max_page_size` 或在 SDK 层补原生 cursor。

## 4. Chat 上下文标记解析

`POST /api/chat` schema 不变；前端把上下文塞进 `message` 开头：

```
[intent=match-analysis match_id=12345 persona=rational risk=7]
{用户实际输入}
```

- 解析位置：ChatAgentService 应用层（`chat-context-marker.ts` 纯函数 + zod 校验）。
- 已知字段：`intent`（match-analysis）、`match_id`（数字串）、`persona`（rational/companion/aggressive/strict）、`risk`（0-10 整数）。重复 key 取最后一个（last-wins）；`match_id` 单独出现（无 intent）时渲染独立的「关联赛事」行。
- 通过 zod 校验的安全字段才允许插值进 system 消息（满足 prompt 注入红线）；模板入 `prompts/chat-agent.context.v1.md` 版本化。
- 剥离标记后的纯用户输入才进入 `<untrusted_input>`、Memory search/write。
- 容错：无标记 / 解析失败 / 字段非法或未知 → 丢弃标记中的非法部分按普通对话处理，不报错。
- 会话历史仍存前端原始 message（含标记），作为 provenance；前端渲染历史时自行剥离（已在交付报告中向前端确认）。

## 5. batch-create 幂等性

`POST /internal/tag/tags/batch-create` 既有实现：同 `category + lang_metadata.en` 已存在 → 恢复/更新并返回现有 `tag_id`，单条失败不阻断（partial failure）。本期只补契约测试，不改实现。

## 6. 配置变更

`config/odd-agent.yaml` 新增顶层 section（维持单一 YAML 红线）：

```yaml
internal_auth:
  service_token_secret_ref: "SERVICE_TOKEN"
```
