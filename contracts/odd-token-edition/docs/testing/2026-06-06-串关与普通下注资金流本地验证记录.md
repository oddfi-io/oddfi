# 串关与普通下注资金流本地验证记录

**日期：** 2026-06-06
**范围：** 本地 Foundry 环境，验证普通下注与串关下注的 ODD 资金流、内部账本、LP 账本、税费分配和风险释放是否符合当前设计。
**结论：** 本轮新增资金流专项测试通过，未发现串关或普通下注资金流不闭合问题。

## 1. 新增测试文件

- `test/FundsFlowMatrix.t.sol`

该测试不依赖外部 RPC，不使用 fork，测试内本地部署：

- `ODDToken`
- `StakingPool`
- `LiquidityPool`
- `BettingPool`
- `BettingSettlementModule`
- `BettingParlayModule`

## 2. 覆盖场景

### 2.1 普通下注：赢单结算与 claim

覆盖：

- 用户下注扣除 `stake + betTax`；
- 无 referrer 时 bet tax 进入 treasury；
- `BettingPool.accountedBalance` 与真实 ODD 余额一致；
- `MarketExposure.totalStakedByOutcome` 和 `payoutByOutcome` 写入正确；
- 用户 `dailyAcceptedAmount / unsettledStake` 写入正确；
- 普通单注结算使用 Global LP + Match LP 分摊 margin / loss；
- `platformReserve` 增加平台 margin；
- `LiquidityPool.requestableLiquidity / globalRequestableLiquidity / payoutWindow` 更新正确；
- claim 时按 gross payout 拉取不足部分 LP payout liquidity；
- payout tax 分配正确；无活跃 staker 时 staking share 经 `StakingPool.notifyReward` 重定向到 treasury；
- claim 后 `requestableLiquidity + outstandingPayoutReserved` 与 LP 实际余额闭合；
- release 后 unused payout reserve 回到 LP，`requestableLiquidity` 与 LP 实际余额闭合。

### 2.2 普通下注：退款

覆盖：

- market 标记 `Refunded` 后通过 `refundBets` 退款；
- 用户只损失 bet tax，本金退回；
- `BettingPool.accountedBalance` 归零；
- 同 bucket 内退款回滚 `dailyAcceptedAmount / unsettledStake`；
- `MarketExposure` 的 stake 与 payout 同步释放。

### 2.3 普通下注：Cash Out

覆盖：

- 返还额低于本金时差额进入 `platformReserve`；
- Cash Out 不回滚 `dailyAcceptedAmount`，但释放 `unsettledStake`；
- 返还额高于本金时，超出本金部分走 LP loss + payout liquidity；
- Cash Out profit 场景 `reservedAmount == paidOutAmount`，LP payout window 闭合。

### 2.4 串关：赢单结算与 claim

覆盖：

- 用户串关下注扣除 `stake + betTax`；
- 串关下注只写 leg market 的 synthetic `payoutByOutcome`，不写 `totalStakedByOutcome`；
- `openParlayMaxPayout` 下单增加、结算释放；
- 底层 market 终态后才能 `settleParlay`；
- 串关赢单只使用 Global LP，不污染任一单场 Match Pool；
- 串关结算按 `stake` 计算 settlement margin；
- 串关 LP loss 通过 `parlayRiskId` 写入 Global LP payout window；
- claim 时按 gross payout 检查余额并拉取不足部分 LP payout liquidity；
- payout tax 分配正确；
- claim 后 `requestableLiquidity + outstandingPayoutReserved` 与 LP 实际余额闭合；
- release 后 unused payout reserve 回到 Global LP，`requestableLiquidity` 与 LP 实际余额闭合。

### 2.5 串关：全 Void / Cancelled 退款

覆盖：

- 全部 leg 为 Void 时，串关进入 `Refundable`；
- 用户领取原 stake；
- 不收 payout tax；
- 不拉 LP；
- 不分配 LP / platform margin；
- `openParlayMaxPayout` 释放；
- `unsettledStake` 释放。

### 2.6 串关：部分退款与不可 Cash Out

覆盖：

- `Void + AH HalfLoss` 时进入 `Refundable`，只退回组合后剩余金额；
- 对亏损部分只计 settlement margin；
- 不收 payout tax；
- 不拉 LP payout liquidity；
- parlay id 不能通过普通 `cashOut(bytes32 betId,...)` 路径提前退出，当前会按非 bet owner 路径 revert。

### 2.7 串关：未 claim reserve 手动释放

覆盖：

- 串关赢单结算后，未 claim 时 `parlayRiskId` 下存在 `reservedAmount > paidOutAmount`；
- `PayoutReserveOutstanding(parlayRiskId,outstandingAmount)` 可给后端索引待检查 residual；
- `SETTLER_ROLE` 调用 `BettingPool.releasePayoutReserve(parlayRiskId)` 后，未实际拉走的 reserve 回到 Global LP；
- `lpLossOffsetRemaining` 同步冲减，避免后续派奖税继续抵扣已释放回 LP 的 booked loss；
- release 后 `reservedAmount == paidOutAmount`，且 `requestableLiquidity == ODD.balanceOf(LiquidityPool)`。

## 4. 资金流结论

本轮本地验证下，普通下注和串关下注资金流符合当前设计：

- 用户扣款、退款、派奖和 Cash Out 到账符合预期；
- `BettingPool.accountedBalance` 与 BettingPool 实际 ODD 余额保持一致；
- 普通单注继续按 Global LP + Match LP 参与结算；
- 串关只使用 Global LP，不占用或污染 Match LP；
- 串关 synthetic exposure 只进入 `payoutByOutcome`，不会把串关本金计入单关 `totalStakedByOutcome`；
- 全退款串关不收 payout tax、不拉 LP；
- 部分退款串关只对亏损部分计 margin，不按胜单派奖收税；
- 普通单注与串关 claim 后的 unused payout reserve 可以通过权限入口释放回 LP；
- 串关没有可用 Cash Out 路径。

## 5. 注意事项

- 本报告执行当轮 `PrecisionConstants.SECONDS_PER_DAY = 3600` 是测试阶段加速配置，因此 `dailyAcceptedAmount` 的 bucket 在当轮本地和测试网语义下是 1 小时，不是自然日。该参数已于 2026-06-13 在当前源码中恢复为 `86400`；跨 bucket 退款口径后续应按自然日配置重新验收。
- 当前 LP loss 会先写 `payoutWindow.reservedAmount`，claim / cashout 再按实际需要拉取 `paidOutAmount`。因此部分场景会存在 `reservedAmount > paidOutAmount`；后端应监听 `PayoutReserveOutstanding(riskId,outstandingAmount)` 索引残留，并在产品/运营确认无需继续保留后调用 `BettingPool.releasePayoutReserve(riskId)` 释放回 LP。
