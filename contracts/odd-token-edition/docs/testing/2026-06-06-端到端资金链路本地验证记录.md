# 端到端资金链路本地验证记录

**日期：** 2026-06-06
**范围：** 本地 Foundry 环境，串联验证 `StakingPool`、`LiquidityPool`、`BettingPool` 普通单注与串关在同一条资金链路中的余额变化、内部账本和 LP / Staker 退出路径。
**结论：** 本轮端到端资金链路测试通过，未发现资金链断裂、重复支付、下注资金丢失或 LP / Staking 账本不闭合问题。

## 2. 覆盖链路

### 2.1 Staking

- staker 质押 `10,000 ODD`；
- 校验 `activeStakeAmount(staker)` 与 `accountedOddBalance()` 均增加 `10,000 ODD`；
- 普通单注派奖税与串关派奖税中的 staking share 进入 `StakingPool.notifyReward`；
- 最终 staker 到期 `unstake`，取回本金与累计奖励。

本轮端到端路径下，staker 最终收到：

- 本金：`10,000 ODD`
- 普通单注派奖税 staking share：`4 ODD`
- 串关派奖税 staking share：`8 ODD`
- 合计赎回：`10,012 ODD`

### 2.2 Liquidity

- LP 存入 Global Pool：`100,000 ODD`；
- LP 存入单场 Match Pool：`100,000 ODD`；
- 普通单注 win/claim 使用 Global + Match 分摊；
- 串关 win/claim 只使用 Global Pool，不占用 Match Pool；
- 普通单注与串关 claim 后释放 unused payout reserve，LP 进入 unbonding，再完成 withdraw；
- 校验 `previewWithdraw(positionId)` 的可提款额与净 PnL。

本轮端到端路径下：

- Global LP 预览可提：`99,702 ODD`，净 PnL：`-298 ODD`
- Match LP 预览可提：`100,000 ODD`，净 PnL：`0 ODD`
- LP 实际 withdraw 到账：`199,702 ODD`

### 2.3 普通单注

- bettor 在单场 `1X2` market 下 `100 ODD` 赢单；
- bettor2 在同一 market 下 `100 ODD` 输单；
- 双方下注均扣除 `stake + 1% bet tax`；
- 比赛比分结算后，赢单进入 `WonUnclaimed`，输单进入 `Lost`；
- bettor claim 后到账符合当前税费与 LP 瀑布设计；
- `BettingPool.accountedBalance()` 与真实 ODD 余额保持一致。

本轮普通单注路径下：

- bettor 初始扣款：`101 ODD`
- bettor claim 后净变化：`+89 ODD`
- treasury 累计收到普通单注相关税费：`6 ODD`
- 普通单注 LP payout window：claim 后 `reservedAmount=100 ODD`、`paidOutAmount=16 ODD`；release 后 `reservedAmount=paidOutAmount=16 ODD`

### 2.4 串关

- bettor2 下 `2串1`，本金 `100 ODD`，组合赔率 `4x`；
- 两个 leg 所属 market 均按比分结算为赢；
- `settleParlay(parlayId)` 后串关进入 `WonUnclaimed`；
- `openParlayMaxPayout` 下单增加、结算后释放；
- `claimParlayPayout(parlayId)` 后状态进入 `WonClaimed`；
- 串关没有 Cash Out 路径；
- 串关只使用 Global Pool。

本轮串关路径下：

- bettor2 串关初始扣款：`101 ODD`
- 串关最高赔付：`400 ODD`
- bettor2 在普通输单 + 串关赢单之后，总净变化：`+178 ODD`
- treasury 在整条链路最终累计收到：`15 ODD`
- staking 奖励累计增加：`12 ODD`
- 串关 LP payout window：claim 后 `reservedAmount=400 ODD`、`paidOutAmount=306 ODD`；release 后 `reservedAmount=paidOutAmount=306 ODD`

## 3. 关键不变量

本轮测试持续校验：

- `BettingPool.accountedBalance() == ODD.balanceOf(BettingPool)`；
- 普通单注 claim 后 bet 状态不可重复 claim；
- 串关 claim 后 parlay 状态进入 `WonClaimed`；
- 普通单注 Match Pool 与 Global Pool 分摊符合当前瀑布；
- 串关只影响 Global Pool；
- release 前 `LiquidityPool.getRequestableLiquidity() + outstandingPayoutReserved == ODD.balanceOf(LiquidityPool)`；
- release 后 `LiquidityPool.getRequestableLiquidity() == ODD.balanceOf(LiquidityPool)`；
- LP withdraw 后 requestable liquidity 清零；
- Staking unstake 后 `accountedOddBalance()` 与合约余额归零。

## 5. 资金链路结论

本轮本地验证下，staking、liquidity、普通单注和串关在同一条端到端链路内符合当前实现预期：

- 用户下注扣款、税费分配、结算、claim 到账与内部账本一致；
- 普通单注继续使用 Global + Match Pool；
- 串关只使用 Global Pool，不污染 Match Pool；
- staker 可获得派奖税 staking share 并在到期赎回；
- LP unused payout reserve 可在确认后释放，随后按 `previewWithdraw` 给出的 PnL 解绑并提款；
- BettingPool、LiquidityPool、StakingPool 的核心余额不变量均闭合。

## 6. 注意事项

- 当前 LP loss 会先写入 `payoutWindow.reservedAmount`，claim / cashout 再按实际需要增加 `paidOutAmount`。普通单注与串关 claim 后可能存在 `reservedAmount > paidOutAmount`，本轮端到端路径通过 `BettingPool.releasePayoutReserve(riskId)` 分别释放普通单注 `84 ODD` 和串关 `94 ODD`，最终 `outstandingPayoutReserved = 0`。
- 后端应监听 `PayoutReserveOutstanding(riskId,outstandingAmount)`：`outstandingAmount > 0` 的 riskId 进入待检查队列，产品/运营确认无需继续保留后由 `SETTLER_ROLE` 调用 `BettingPool.releasePayoutReserve(riskId)`。本期不新增链上 claim 过期状态机，避免超出最小改动范围。
- 本报告执行当轮 `PrecisionConstants.SECONDS_PER_DAY = 3600` 是测试阶段加速配置，因此当轮本地与测试网中的 daily bucket 为 1 小时，不是自然日；该参数已于 2026-06-13 在当前源码中恢复为 `86400`。
