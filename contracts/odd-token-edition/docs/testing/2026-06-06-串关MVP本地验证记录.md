## 4. 关键观察

- `BettingPool` 主合约体积非常接近 EIP-170 上限，因此最终 ABI 使用 `parlays(parlayId)`、`parlayLegs(parlayId,index)`、`marketFinalResults(marketId)` 自动 getter，未保留聚合 getter；
- 2026-06-07 已将已模块化入口的 wrapper 改为直接转发 `msg.data`，外部 ABI 不变，主合约 runtime margin 从 `63B` 提升到 `699B`；
- 串关没有 Cash Out 入口，ABI 检查未发现 `cashOutParlay / quoteParlay`；
- `openParlayMaxPayout` 在下注后增加，在 `settleParlay` 所有终局路径释放；
- `LiquidityPool.PayoutReserveOutstanding(parlayRiskId,outstandingAmount)` 可索引未实际拉走的 payout reserve residual，运营确认后通过 `BettingPool.releasePayoutReserve(parlayRiskId)` 手动释放；
- `estimatedValue` 仅由 Lens 只读计算，不写状态，不触发资金流。
