## 适用范围

本文档覆盖 **ODD 代币在 BettingPool 应用层的税收机制**（下注税 / 派奖税）、推荐关系绑定规则、推荐人奖励累积与 Claim 规则，以及 ODD 合约层的 Clean BEP-20 属性声明。

不覆盖：代币分配结构（私募/公募/团队/生态），价格稳定机制（战略储备买盘），层级推荐（S1–S5），质押奖励分配细节，对赌池瀑布顺序。

## 角色与权限

| 角色 | 可执行操作 | 不可执行操作 |
|------|---------|-----------|
| 普通用户 | 首次下注前绑定推荐人、调用 placeBet 下注（自动缴下注税）、claimPayout 领派彩（自动扣派奖税） | 修改税率、修改推荐关系、跨地址转移推荐累积 |
| 推荐人 | 调用 `claimReferralRewards(oddAmount)` 领取 ODD 奖励，或调用 `claimUSDTReferralRewards(...)` 领取 USDT 奖励 | 主动修改推荐关系 |
| 平台 Owner（多签） | 调整下注税率（上限 3%）、调整派奖税率（上限 10%）、调整派奖税四项分配比例（四项合计 = 当前派奖税率；默认 2pp/1pp/1pp/1pp）、配置平台金库地址、暂停/恢复 BettingPool | 修改 ODD 合约层（Clean BEP-20，合约已锁权限） |
| BettingPool 合约 | 执行下注税扣除、在 `settle` 锁定胜单派奖税快照、在 `claimPayout` 按锁定快照扣税并分配、执行推荐奖励 ODD / USDT Claim | — |
| StakingPool 合约 | 被动接收胜单在 `settle` 时锁定给质押池的派奖份额（默认 2pp）注入奖励池 | — |

> ODD.sol 当前仅保留标准 ERC20 + AccessControl + Pausable + UUPS，治理权限只覆盖 `pause/unpause` 与升级，**不再** 保留税率、白名单、推荐关系、成本基准相关管理函数。

## 正常流程

### 1. 推荐关系绑定

**触发时机：** 用户在 BettingPool 首次调用 `placeBet()` 前。

**调用路径：** `BettingPool.bindReferrer(address referrer)` 或在 `placeBet()` 参数中传入 referrer（首次下注时自动尝试绑定）。

**绑定规则：**
- 用户当前无推荐人（`referrers[user] == address(0)`）时可绑定。
- 推荐人不可为用户自身。
- 推荐人不可为零地址。
- **不再以"推荐人有效质押量 > 0"为资格门槛**（v1 门槛废止）。
- 绑定后永久有效，不可更改，不可解绑。
- 绑定操作仅可执行一次，二次调用 `bindReferrer` 拒绝。

**首次下注未携带 referrer：** 用户标记为"无推荐绑定用户"；此后任意时刻仍可调用 `bindReferrer` 补绑。补绑后：
- 对之后的新下注立即生效。
- 对**尚未结算**的历史订单，按该订单实际 `settle` 时的推荐关系归属判定派奖推荐份额。
- 对**已结算**的历史订单不追溯。

> v2 与 v1 的差异：推荐关系存储位置从 `ODD.sol` 迁至 `BettingPool_ODD.sol`；绑定时机从"首次买入 ODD"改为"首次 placeBet"；取消"根节点地址"概念与"有效质押 > 0"资格门槛。

---

### 2. 下注税机制（默认 1%，可配置）

**触发条件：** 用户调用 `BettingPool.placeBet(amount, ...)` 下注时，按当前下注税率（默认 1%，上限 3%）**额外**扣除 ODD 作为下注税（不占用下注筹码 amount）。

**计算：**
- 下注筹码 = amount（原额进入对赌池作为注码）。
- 下注税 = amount × 当前下注税率。
- 用户总扣款 = amount + 下注税（ODD）。

**分配路径：**

| 情形 | 当前下注税去向 |
|------|--------------|
| 有推荐人（referrers[user] ≠ 0） | 全额累积至 `referrerRewardsOdd[referrer]`（以 ODD 计） |
| 无推荐绑定用户（referrers[user] == 0） | 全额转入平台金库地址 |

**最小下注金额限制：**
- `placeBet()` 入口强制 `require(amount >= 100 ODD)`（即 100e18 wei）；与最小质押量（100 ODD）持平，过滤粉尘注单，避免 referrerRewardsOdd 与质押账本被微注单拖大。
- 按默认下注税率 1% 计算，最小应扣 1 ODD；按默认派奖税率 5% 计算，若最小派彩按 `100 × 1.01 = 101 ODD` 估算，则最小应扣约 5.05 ODD，均远超精度溢舍阈值。

---

### 3. 派奖税机制（默认 5%，税率与四项比例均可配置）

**触发条件：**
- 订单在 `settle` 时若被标记为胜单，系统同时锁定该订单的**派奖税率快照**与**四项分配比例快照**。
- 用户后续调用 `BettingPool.claimPayout(orderId)` 领取该笔**获胜**派彩时，按该订单在 `settle` 时锁定的税率与分配比例执行扣税和分配。

**适用范围：**
- **仅对胜注的实际派彩征收**（派彩 = 本金 × 赔率）。
- **输注、退款、平局返本** 不征派奖税。
- 赔率 < 1.00（理论上不存在此情形，但合约层兜底：若派彩 ≤ 本金，按"退款"处理，不征税）。

**计算：**
- 派彩金额 = 订单结算派彩（ODD）。
- 派奖税 = 派彩金额 × 该订单在 `settle` 时锁定的派奖税率。
- 用户实际到账 = 派彩金额 - 派奖税。

**分配路径（以订单 `settle` 时锁定的配置为准）：**

| 去向 | 默认占比（可配置） | 说明 |
|------|----------------|------|
| 质押奖励池（StakingPool） | 2pp | 该订单在 `settle` 时锁定给质押池的份额；默认按活跃质押用户 stake 权重分红（详见质押_规则设计.md） |
| L3 派奖税缓冲（taxBuffer） | 1pp | 该订单在 `settle` 时锁定给对赌池 taxBuffer 的份额；详见对赌池_准备金瀑布_规则设计.md |
| 平台金库 | 1pp | 该订单在 `settle` 时锁定给平台金库的份额 |
| 推荐人 | 1pp | 该订单在 `settle` 时锁定给推荐人的份额；若订单在 `settle` 时快照中存在推荐人，则累积至 `referrerRewardsOdd[referrer]`，否则并入平台金库 |
| **合计** | **默认 5pp** | 四项之和必须严格等于该订单在 `settle` 时锁定的派奖税率 |

**配置生效规则：**
- 默认派奖税率为 `5%`。
- 默认配置为 `2pp / 1pp / 1pp / 1pp`。
- 平台可在运营期调整四项比例，但四项之和必须严格等于当前派奖税率。
- 新配置仅对配置生效后**新进入 `settle`** 的胜单生效。
- 已在旧配置下完成 `settle` 的胜单，即使尚未 `claimPayout`，也继续沿用其锁定快照，不受后续配置变更影响。

**无推荐绑定用户的派奖税分配退化：**
- 质押池份额与 L3 份额按该订单锁定配置正常执行。
- 推荐人份额在 `referrers[user] == address(0)` 时并入平台金库。
- 即无绑定用户的派奖税中，平台最终取得 = 平台份额 + 推荐人份额（均以该订单锁定配置为准）。

### 4. 推荐人奖励 Claim

**累积形式：** 所有推荐奖励（下注税 1% + 胜单在 `settle` 时锁定给推荐人的派奖份额，默认 1pp）以 **ODD** 形式累积至 `referrerRewardsOdd[推荐人地址]`。

**Claim 流程：**
1. 推荐人可调用 `BettingPool.claimReferralRewards(uint256 oddAmount)`，按需领取 ODD。
2. 合约读取 `referrerRewardsOdd[msg.sender]`，若为 0 直接 revert。
3. 校验 `oddAmount > 0` 且 `oddAmount <= 当前可领取余额`。
4. 扣减推荐奖励主账并直接 transfer ODD 给领取人。
5. 触发事件 `ReferralClaimed(推荐人, ODD 到账量)`。

**可选 USDT Claim 流程：**
1. 推荐人可调用 `BettingPool.claimUSDTReferralRewards(...)`。
2. 后端签名授权本次 Claim，签名中包含：用户地址、当前奖励 ODD 数量、最低 USDT 结果、过期时间、nonce。
3. BettingPool 校验签名、过期时间和 nonce 后，使用治理配置的 Pancake V3 Router 与 USDT token 将当前奖励 ODD 直接换成 USDT 打给推荐人。
4. 合约以推荐人 USDT 余额前后差额作为真实到账量，并校验不低于用户滑点要求和后端签名最低要求。
5. 触发事件 `ReferralClaimedUSDT(推荐人, ODD 兑换量, USDT 到账量, 成交价格)`。

**推荐人承担的成本：**
- gas（Claim 调用成本）。

**Claim 频率：** 暂不限制 Claim 次数或频率；V1.1 迭代观察头两周 Claim 行为后决定是否加"24h 累积上限"（见对应"当前限制 3"）。

### 5. Clean BEP-20 属性声明

ODD.sol 合约层**不包含**以下 v1 机制：

| v1 机制 | v2 状态 |
|--------|--------|
| `_transfer` 内的买入税 5% 路径 | 已删除 |
| `_transfer` 内的卖出利润税 25% 路径 | 已删除 |
| `referrers[user]` 推荐关系存储 | 已迁至 BettingPool |
| 单笔卖出上限 10% | 已删除 |
| 卖出冷却 1 分钟 | 已删除 |
| 销毁 1pp → 0xdead | 已删除 |
| 免税白名单 | 已删除（无税故无白名单需求） |
| 推荐人 stakeFor 7 天锁定 | 已删除（推荐奖励改为 Claim + swap） |

ODD.sol 保留：
- OpenZeppelin **ERC20** 标准接口（transfer / transferFrom / approve / totalSupply / balanceOf / allowance）。
- **AccessControl + Pausable + UUPS**；治理侧当前通过角色控制 `pause/unpause` 与升级，不再保留税与推荐关系管理函数。
- 固定总量 **100,000,000 ODD**（部署时一次铸造至 TGE 分配地址，此后不再增发）。

## 异常流程

| 场景 | 触发条件 | 处理方式 |
|------|---------|---------|
| 用户二次绑定推荐人 | `referrers[user] != address(0)` | revert `BettingPool: referrer already bound` |
| 用户自我推荐 | `referrer == msg.sender` | revert `BettingPool: self-refer` |
| 推荐人为零地址 | `referrer == address(0)` | revert `BettingPool: zero referrer` |
| 下注金额 < 100 ODD | `amount < 100e18` | revert `BettingPool: amount below min` |
| ODD 余额不足支付 amount + 下注税 | `balanceOf(user) < amount + betTax` | revert `BettingPool: insufficient ODD` |
| 派奖税计算后用户到账 = 0（派彩 < 0.00001 ODD 等极小值） | `payout - tax == 0` | revert `BettingPool: payout too small`（理论上 placeBet min = 100 ODD 下不可能触发，仅作为合约层兜底） |
| Claim 时 `referrerRewardsOdd[user] == 0` | 无累积余额 | revert `BettingPool: nothing to claim` |
| BettingPool 暂停 | Owner 调用 pause | placeBet / claimPayout / claimReferralRewards / claimUSDTReferralRewards 均 revert |
| ODD 合约暂停 | ODD.sol Owner 调用 pause | 所有 ODD 转账失败（含 BettingPool 内部转账）；BettingPool 操作均 revert |

## 边界条件

| 边界 | 规则 |
|------|------|
| 下注税向上舍入 vs 向下舍入 | 向下舍入（floor），用户实付不超过 `amount + floor(amount × 当前下注税率)`；舍入余数归 BettingPool 合约账本 |
| 派奖税向上舍入 vs 向下舍入 | 向下舍入（floor），用户到账 = `payout - tax` 的 floor 结果；舍入余数统一并入平台金库，不改变其余各项按该订单锁定配置的应分比例 |
| 无推荐绑定用户补绑 | 补绑后对未来下注立即生效；对尚未结算订单以该订单 settle 时快照为准；已结算订单不追溯 |
| 推荐人自身为无推荐绑定用户 | 不影响其作为他人推荐人的身份；其自身的下注/派奖税仍按"无绑定"处理 |
| Claim 时推荐人本身被冻结（平台风控黑名单，若有） | BettingPool 仅实现 claim 逻辑，不做黑名单校验；黑名单由链下账户层拦截 Claim 调用 |
| 派奖税四项分配之和 | 严格 = 该订单在 `settle` 时锁定的派奖税率；默认 = 5pp |
| 下注税归属计算的时间点 | 以 `placeBet` 执行时 `referrers[user]` 为准；下注后即使补绑，也不追溯此笔 |
| 派奖税归属计算的时间点 | 推荐关系、派奖税率、四项分配比例均以订单 `settle` 时锁定的快照为准 |
| 推荐人份额遇无绑定用户 | 该订单锁定的推荐人份额全部并入平台金库；不影响质押池份额与 L3 份额 |

## 当前限制

1. **无推荐绑定用户占比过高时平台实际税负集中**（v2.5 风险 #5）：无绑定用户的下注税 1% 与派奖税中锁定给推荐人的份额均归平台；若平台配置本身平台份额较高，平台实际税负会进一步集中。叙事上为"平台多收"，不影响用户体验；长期由运营侧（KOL 内测绑定率指标）驱动绑定率。**修复前为已知可接受风险。**
2. **推荐人 Claim 频率上限未定**（v2.6 不确定项 #1）：V1.1 观察首两周 Claim 行为后决定；当前暂不限频。
3. **BettingPool 合约审计面扩大**（v2.5 风险 #6）：两点税 + referrerRewardsOdd + claimReferralRewards 三个函数为高风险面，主网部署前第三方审计专项覆盖。**修复前为已知可接受风险。**
4. **L3 taxBuffer 冷启动填充慢**（v2.5 风险 #3）：派奖税中分配给对赌池的锁定默认份额仅 1pp，相比 v1 卖出税 4pp 流入速度大幅降低；taxBufferCap 500k ODD 冷启动期可能长期未填满，不阻塞 L4 兜底；内测两周后复评是否调整 cap。**修复前为已知可接受风险。**

## 人工介入点

| 触发条件 | 介入形式 | 负责方 |
|---------|---------|-------|
| Claim 函数发现异常消耗（如批量套利 gas 攻击） | Owner 调用 BettingPool.pause，排查后升级合约 | Hawk + 产品 |
| ODD 合约层发现漏洞 | ODD.sol Owner 调用 pause，协调 BettingPool pause 保持状态一致；热修升级走多签流程 | Hawk |
| 无绑定用户占比长期 > 50% | 运营侧启动绑定率促销（如首次绑定发空投） | 运营 |
| 第三方审计发现高危问题 | 按审计报告处置：参数调整走多签 / 合约升级 / 停止上币 | Hawk + 产品 + 投资人 |

## 不适用范围

- **代币分配结构**（私募/公募/团队/生态/流动性）的释放曲线，由独立的代币经济材料覆盖；当前仓库未收录。
- **战略储备价格稳定机制**（平台准备金池的买盘时机与规模），由独立运营规则覆盖；当前仓库未收录。
- **层级推荐返佣**（S1–S5 差加成）：链上合约仅支持单层推荐关系；层级分润由链下生态激励发放，不在本文档范围。
