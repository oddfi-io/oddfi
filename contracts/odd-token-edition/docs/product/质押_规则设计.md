## 角色与权限

| 角色 | 可执行操作 | 不可执行操作 |
|------|---------|-----------|
| 普通用户 | 质押（stake）、到期赎回（unstake）、提前赎回（earlyUnstake） | 调整档位参数、解锁他人仓位 |
| BettingPool 合约 | 调用 `StakingPool.notifyReward` 注入胜单在 `settle` 时锁定给质押池的派奖份额（默认 2pp） | — |
| 平台 Owner（多签） | 调整 VIP 门槛、调整最小质押量、暂停/恢复合约 | — |
| 后端（Remy） | 查询 VIP 等级（getUserTier）、查询有效质押量（getActiveStakeAmount） | 直接修改用户质押状态 |

## 正常流程

### 1. 质押操作

**前置条件：**
- 用户 ODD 余额 ≥ 最小质押量（100 ODD）
- 合约未暂停

**步骤：**
1. 用户选择锁定档位（MVP UI 开放：7 / 30 / 60 / 90 天）。
2. 输入质押数量（≥ 100 ODD）。
3. 用户确认授权并提交。
4. ODD 从用户钱包转入质押合约。
5. 系统记录质押仓位：
   - 本金金额
   - 锁定天数
   - 收益乘数（按档位）
   - 解锁时间 = 质押时间 + 锁定天数
   - rewardDebt = 当前全局 rewardPerShare
6. 全网总权重 += 本金 × 乘数。
7. 有效质押量 += 本金，VIP 等级立即更新（升级立即生效）。

**锁定档位与乘数（MVP UI 开放档位）：**

| 档位 | 锁定天数 | 收益乘数 | UI 开放 |
|------|---------|---------|--------|
| 最短档 | 7 天 | 0.5x | ✅（用户自愿，v2 起不再由合约代建） |
| 基础档 | 30 天 | 1.0x | ✅ |
| 中期档 | 60 天 | 1.8x | ✅ |
| 长期档 | 90 天 | 4.0x | ✅ |
| 超长档 | 180 天 | 8.0x | ❌（合约已实现，UI 后续版本开放） |
| 最长档 | 360 天 | 15.0x | ❌（合约已实现，UI 后续版本开放） |

**最小质押量：** 100 ODD（低于此值拒绝质押）。

---

### 2. 收益分配

**收益来源：**

| 来源 | 注入时机 | 数量 |
|------|---------|------|
| BettingPool 派奖税质押池份额 | 用户 claimPayout 时 | 以该胜单在 `settle` 时锁定给质押池的份额计入；默认 = 派彩 × 2% |
| 提前赎回罚没收益 | 用户提前赎回时 | 该用户已累计收益中的正收益部分（若为正） |

> v2 废止：v1 的"买入税 5%（推荐人无效时）"与"卖出利润税 9pp"两条收益源已随代币税制重构关闭，不再注入质押奖励池。

**分配公式（rewardPerShare 模式）：**
- 每次收益注入时：rewardPerShare += 注入量 × 1e18 ÷ 全网总权重。
- 用户当前可领收益 = 用户权重 × (当前 rewardPerShare - 创建仓位时 rewardDebt) ÷ 1e18。
- 收益实时累积，无固定结算时间，不需要用户手动领取（随赎回一并支付）。

**收益归属：**
- 收益归各个质押仓位，多个仓位独立计算。
- 当全网总权重 = 0 时（无任何活跃质押），注入的收益直接归平台金库，不进入 rewardPerShare 分配。

---

### 3. 到期正常赎回

**前置条件：** 当前时间 ≥ 仓位解锁时间。

**步骤：**
1. 用户在 Unstake Tab 找到已到期（Ready）仓位，点击赎回。
2. 计算当前累计收益 = 仓位权重 × (rewardPerShare - rewardDebt) ÷ 1e18。
3. 将仓位设为非活跃（active = false）。
4. 全网总权重 -= 本金 × 乘数。
5. 有效质押量 -= 本金，VIP 等级立即更新（降级立即生效）。
6. 向用户转出：本金 + 累计收益（100% 全额返还）。

---

### 4. 提前赎回

**前置条件：** 当前时间 < 仓位解锁时间（仓位处于 Active 锁定状态）。

**步骤：**
1. 用户点击"Early Unstake"，前端展示二次确认弹窗，明确显示：
   - 可收回：本金（100% 返还）
   - 罚没：当前已累计收益中的正收益部分
   - 罚没金额：X ODD
2. 用户确认提前赎回。
3. 计算当前累计收益 = 仓位权重 × (rewardPerShare - rewardDebt) ÷ 1e18；`penalty = max(当前累计收益, 0)`。
4. 将仓位设为非活跃。
5. 全网总权重 -= 本金 × 乘数。
6. 有效质押量 -= 本金，VIP 等级立即更新。
7. 向用户转出：本金（100%）。
8. 罚没处理：
   - 若 `penalty > 0` 且全网总权重 > 0：rewardPerShare += penalty × 1e18 ÷ 全网总权重（分配给留存用户）。
   - 若 `penalty > 0` 且全网总权重 = 0（全部用户同时提前赎回）：罚没金额归平台。
   - 若 `penalty = 0`：无罚没，也不向用户额外追偿。

**提前赎回规则：**
- 不分档次，无论剩余锁定时间多少，一律按以上规则处理。
- 本金始终全额返还。
- 仅已累计收益中的正收益部分会被罚没；负收益不向用户额外追偿。

---

### 5. VIP 等级判定

**判定时机：** 实时判定，质押量变化（质押/赎回）后立即生效，无保级期。

**判定依据：** 用户当前有效质押量（所有活跃仓位本金之和）。

**VIP 等级与每日下注限额：**

| 等级 | 有效质押门槛 | 每日下注限额（ODD） | 折合 USD（$0.1/ODD） |
|------|-----------|-----------------|-------------------|
| 普通 | 0 | 10,000 ODD | $1,000 |
| VIP 1 | ≥ 1,000 ODD | 50,000 ODD | $5,000 |
| VIP 2 | ≥ 5,000 ODD | 100,000 ODD | $10,000 |
| VIP 3 | ≥ 20,000 ODD | 150,000 ODD | $15,000 |
| VIP 4 | ≥ 50,000 ODD | 200,000 ODD | $20,000 |
| VIP 5 | ≥ 100,000 ODD | 250,000 ODD | $25,000 |
| VIP 6 | ≥ 200,000 ODD | 300,000 ODD | $30,000 |
| VIP 7 | ≥ 500,000 ODD | 400,000 ODD | $40,000 |
| VIP 8 | ≥ 1,000,000 ODD | 500,000 ODD | $50,000 |
| VIP 9 | ≥ 2,000,000 ODD | 750,000 ODD | $75,000 |
| VIP 10 | ≥ 5,000,000 ODD | 1,000,000 ODD | $100,000 |

**限额汇率：** 固定 $0.1/ODD，不随 ODD 市价浮动。

**未平仓额度规则：**
- 当前未平仓总额 ≤ 5,000 ODD：无需质押，自由下注。
- 当前未平仓总额 > 5,000 ODD：累计未平仓额不得超过有效质押量。

## 异常流程

| 场景 | 触发条件 | 处理方式 |
|------|---------|---------|
| 质押量低于最小值 | 输入 < 100 ODD | 前端拦截，提示"Minimum 100 ODD"，不提交链上 |
| 质押时余额不足 | 钱包 ODD < 质押数量 | 前端拦截，提示"Insufficient balance"，不提交链上 |
| 到期赎回时合约余额不足 | 极端情况下合约 ODD 余量 < 应付金额 | 触发人工介入告警，运营协调补充，用户等待 |
| 提前赎回二次确认弹窗取消 | 用户点击取消 | 不执行任何链上操作，仓位状态不变 |
| 合约暂停时提交质押 | Owner 已调用 pause | 交易失败，等待 unpause 后重试 |
| BettingPool 暂停时 claimPayout 失败导致质押池份额未注入 | BettingPool.pause | 质押 APR 暂停累积；待 BettingPool 恢复后重建注入流；此期间质押收益不回溯补偿 |
| StakingPool 暂停期间用户操作质押 | StakingPool.pause | `stake / unstake / earlyUnstake` 失败；BettingPool 已结算胜单 `claimPayout` 仍可注入质押池份额，避免用户卡单 |

## 边界条件

| 边界 | 规则 |
|------|------|
| 最小质押量 | 100 ODD，低于此值拒绝 |
| 全网总权重 = 0 时注入奖励 | 直接归平台金库，不做 rewardPerShare 分配 |
| 同时提前赎回全部用户（极端场景） | 罚没金额因总权重 = 0 而归平台，不丢失 |
| 有效质押量变为 0 后的 VIP 降级 | 赎回完成后立即降级，下一笔下注使用新等级限额 |
| 未平仓额度判定时机 | 每次下注时实时查询有效质押量，不缓存 |
| 7 天档位乘数 | 0.5x（v1 为推荐人 stakeFor 专用，v2 降级为用户自愿档，乘数值不变） |
| 180/360 天档位合约支持、UI 不开放 | UI 层拦截选择；若直接调用合约 API（非前端用户）仍可进档 |

## 当前限制

1. **totalWeightedShares = 0 边界已收口：** 全网质押归零时，胜单在 `settle` 时锁定给质押池的派奖份额（默认 2pp）或罚没金额直接归平台金库，不再留存在合约里悬空。
2. **180/360 天档位 UI 未开放：** 合约已实现，MVP 阶段 UI 不展示这两档，后续版本加入选择器。
3. **7 天档位 v2 起为用户自愿档：** 合约不再自动为推荐人创建仓位；UI 保留选项；使用率低于 5% 时作为 V1.1 产品决策项复评。
4. **冷启动期 APR 低风险：** 胜单在 `settle` 时锁定给质押池的默认份额仅 2pp，在流水起量前分红速度有限；运营侧预注入种子质押（10 万 ODD）规避 totalWeightedShares=0；平台金库补贴机制为 V1.1 决策项。
5. **推荐人资格门槛（isActiveStaker）已废止：** 推荐关系与质押解耦，推荐资格不再与质押状态挂钩（由代币_规则设计.md §1 负责）。

## 人工介入点

| 触发条件 | 介入形式 | 负责方 |
|---------|---------|-------|
| 到期赎回时合约余额不足 | 告警，补充合约 ODD 余量后重试 | 运营 + Hawk |
| 全网质押量长期为 0（冷启动期） | 运营预注入种子质押 10 万 ODD | 运营 |
| StakingPool 暂停 | 冻结用户质押/赎回操作；无需因质押池暂停同步暂停 BettingPool 领奖路径 | Hawk + 产品 |
| 冷启动期 APR 持续低于 5%（V1.1 决策点） | 产品决策是否从平台金库份额拨付补贴 | 产品 + 运营 |
