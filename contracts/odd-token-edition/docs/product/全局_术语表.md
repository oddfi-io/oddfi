## A — 对赌池模块

| 术语 | 定义 |
|------|------|
| 市场（Market） | 一场比赛内的单个盘口，如"让球 -0.75"，对应一个独立的资金池和信号灯状态 |
| 方向（Direction） | 市场内的单一结果选项，如"主让赢"或"客让赢"，用索引 0/1/2 区分 |
| 最坏亏损（Worst Case Loss，WCL） | 若某方向结果发生，平台净亏损额 = `P_i - S_i - ΣS_j`，等价于 `P_i - totalStake`；V2 起按每笔注单 `lockedOdds` 累计真实赔付额，不再用单一 Base Odds 估算历史敞口 |
| `S_i` | 方向 i 累计有效 stake，本金口径 |
| `P_i / payoutByOutcome` | 方向 i 累计应付赔付额，含本金返还；下注成交时按 `acceptedAmount × lockedOdds / 1e4` 增加，退款或结算释放时按同口径减少 |
| lockedOdds | 注单成交瞬间锁定的实际赔率，精度 `1e4`；下注后永久不随 Base Odds 或市场报价变化回算 |
| 信号灯（Signal Light） | 基于 WCL 对某方向接单风险的四级判定：绿灯 / 黄灯 / 橙灯 / 红灯 |
| 绿灯 | 0 ≤ WCL ≤ 80,000 ODD，不压缩赔率，全额成交 |
| 黄灯 | 80,000 ODD < WCL ≤ 180,000 ODD，压缩赔率，全额成交，前端提示 |
| 橙灯 | 180,000 ODD < WCL ≤ 280,000 ODD，压缩赔率更多，全额成交，前端提示 |
| 红灯 | WCL > 280,000 ODD，该方向停止接单，仅部分成交至阈值边界 |
| 基准赔率（Base Odds） | 后端/脚本以 Sportmonks 参考赔率经四步法生成的初始赔率：隐含概率 → 去除书商 margin → 应用 OddFi 10% Margin → 取倒数并按 0.01 tick 取整；禁止使用 `refOdds × (1 - Margin)` 简化公式 |
| 压缩率（r） | 对重仓方向赔率执行的折减比例，范围 0%–12% |
| 上浮系数（k） | 轻仓上浮率 = 压缩率 × k，当前锁定值 k=1.0（完全对称） |
| 重仓方向 | WCL 值最大的方向 |
| 轻仓方向 | WCL 值非最大的其余方向 |
| Push（走盘） | AH 整数线或 +0 线在特定比分下出现的本金退回结果；full push 不产生派奖税、Margin 或瀑布 |
| 半赢（Half Win） | AH 四分之一线结果，一半本金退回，一半本金按锁定赔率进入待 claim |
| 半输（Half Loss） | AH 四分之一线结果，一半本金退回，一半本金判负并进入 loserStakes |
| 部分成交（Partial Fill） | 注单金额超过红灯阈值时，仅成交至阈值边界，超出部分原路退回用户余额 |
| Margin | 平台内置于赔率中的收益率，锁定为 10%；每笔投注总额的 10% 归平台所有 |
| Margin 分配 | 每场结算后 Margin 的 80% 分配给 LP 池，20% 归平台 |
| 滑点（Slippage） | 单笔注单超过 10,000 ODD 时，因注单本身改变资金分布导致的赔率折后差异 |
| previewSignal | 下注前由后端调用的预算接口，输入实时赔率（从 Redis 读取）和下注参数，返回预期信号灯状态和成交金额，供前端展示确认框 |
| 外部漂移（External Drift） | 我方 Base Odds 与 Sportmonks 实时赔率的百分比偏差；任一方向偏差 ≥ 5% 触发 Base Odds 强制更新 |
| 聚合风险级别 | 单场三个市场信号灯的整体风险判定，用于触发人工介入告警 |
| 损失瀑布（Loss Waterfall） | 结算时平台赔付资金的承担顺序；OddFi 采用固定四层：L1 输家下注筹码 → L2 用户 LP → L3 派奖税缓冲 → L4 平台准备金 |
| L1 输家下注筹码（loserStakes） | 该市场中所有落败方向的投注之和；获胜方向赔付首先由该资金抵扣；每场结算后清零 |
| L2 用户 LP 承担 | 全局池（poolId=0）与比赛独立池（poolId=matchId）按当前存量比例共同分摊 L1 之后的赔付缺口；每个仓位的 P&L 相应扣减 |
| L3 派奖税缓冲（taxBuffer） | 对赌池层的缓冲账户，累积来自**胜单在 `settle` 时锁定给对赌池的派奖份额**（默认 1pp，v2.5 前为卖出利润税 4pp）；承担 L2 之后的赔付缺口；单调有上限 taxBufferCap |
| L4 平台准备金（reserveBalance / platformReserve） | 由平台代币分配初始化（15,000,000 ODD）的兜底层；仅在 L1/L2/L3 均无法覆盖时动用；外部人工充值必须通过 addPlatformReserve；协议内自动记账增量（如平台 20% Margin、无 LP 时的 Margin 80%）可直接计入 |
| taxBufferCap | taxBuffer 的上限，锁定 500,000 ODD；超过上限部分溢出至 reserveBalance |
| lpLossOffsetRemaining | L2 用户 LP 已承担亏损中尚未被后续派奖税缓冲份额冲抵的指标余额；它不是平台欠 LP 的应付债务，不触发向 LiquidityPool 转账，也不反向恢复 LP 的 `lossPerPrincipal`；冲抵顺序为 lpLossOffsetRemaining → taxBuffer → reserveBalance |
| emergencyFloor | 准备金熔断阈值，锁定 100,000 ODD；准备金余额 ≤ 该阈值自动暂停接单，等待运营补仓 |
| ReserveTapped | 准备金被动用事件；任何 L4 扣减（无论金额）都触发该事件并驱动 P1 级事件告警 |
| 阶梯阈值告警 | 准备金每减少 100,000 ODD 触发一次 P2 级告警，共 150 级；与事件告警构成双保险 |
| addPlatformReserve | 唯一合法的外部人工准备金充值入口；直接转账 ODD 至 BettingPool 地址不计入 platformReserve，协议内自动记账增量除外 |

## B — 质押模块

| 术语 | 定义 |
|------|------|
| 质押（Staking） | 用户将 ODD 锁入质押合约，锁定期内享受收益分配权，期满后取回本金与收益 |
| 质押档位 | 按锁定天数区分的六档：7 天 / 30 天 / 60 天 / 90 天 / 180 天 / 360 天 |
| 收益乘数（Multiplier） | 各档位的收益权重倍数：7d=0.5x / 30d=1.0x / 60d=1.8x / 90d=4.0x / 180d=8.0x / 360d=15.0x |
| 用户权重 | 质押量 × 收益乘数，用于计算该用户在全网总权重中的分配比例 |
| 全网总权重 | 所有活跃仓位的质押量 × 各自乘数之和 |
| rewardPerShare | 全局累计变量，每单位权重已分配的收益总额，用于按权重分配奖励 |
| 有效质押量 | 用户当前所有活跃（未到期、未赎回）质押仓位的本金总和，用于 VIP 等级判定和未平仓上限计算 |
| VIP 等级 | 由实时有效质押量决定的用户权益等级（普通 / VIP1–VIP10），影响每日下注限额、推送条数等权益 |
| 每日下注限额 | 用户每日（UTC 00:00 重置）可累计下注的最大 ODD 数量，按 VIP 等级区分 |
| 未平仓额度 | 用户当前所有尚未结算注单的 ODD 总额；≤ 5,000 ODD 免质押要求，> 5,000 ODD 时不得超过有效质押量 |
| 正常赎回 | 到期后申请赎回，本金 100% 返还，已累计收益 100% 返还 |
| 提前赎回 | 锁定期内申请赎回，本金 100% 返还，已累计净收益 100% 罚没并重新分配给留存用户 |

> **v2.0 废止术语：** ~~推荐人 stakeFor~~、~~isActiveStaker~~。原由 ODD 买入税 5% 触发的推荐人自动质押路径在 v2.5 税制重构后完全移除；推荐人资格不再要求"有效质押 > 0"。

## C — 做市模块

| 术语 | 定义 |
|------|------|
| LP（流动性提供者） | 向 Pools 存入 ODD 的用户，成为平台对赌池的做市方，共享 Margin 收益并承担赔付风险 |
| 全局池（Global Pool） | poolId=0，跨所有比赛分散风险的做市池，锁仓期 7/14/28/60/90 天 |
| 比赛独立池（Match Pool） | poolId=matchId，对应单场比赛的做市池，比赛开赛后停止存入，比赛结束自动解锁 |
| 平台准备金池 | 由平台代币分配（15,000,000 ODD）初始化的对赌池兜底层；在损失瀑布中位于 L4，仅在 L1 输家筹码、L2 用户 LP、L3 taxBuffer 均不足时动用；补充来源为**胜单在 `settle` 时锁定给对赌池的份额**在 lpLossOffsetRemaining 已冲抵为 0 且 taxBuffer 已满后的溢出部分、平台 20% Margin，以及无 LP 时自动转入的 Margin 80% |
| 锁仓乘数 | 全局池档位展示乘数：7d=0.5x / 14d=1.0x / 28d=1.8x / 60d=2.5x / 90d=3.5x；比赛独立池固定 1.0x。当前版本不参与实际 Margin/P&L 结算 |
| 仓位（Position） | LP 存入的单次记录，含存入量、锁仓档位、展示乘数、解锁时间、累计 P&L 等 |
| Epoch | 解绑等待计时单位，1 Epoch = 1 天（UTC 00:00 为边界），申请解绑后需等待 2 个完整 Epoch 方可提取 |
| Ready | 锁仓已到期、可发起 `requestUnbond` 的状态 |
| Unbonding | 用户发起解绑后的等待状态，进入后停止收益累积，不再承担新的赔付亏损 |
| Withdrawable | 经过 2 个完整 Epoch 后，仓位可执行提取的状态 |
| P&L（盈亏） | 仓位存续期间分配到的 Margin 收益与承担的赔付亏损之差；可为正（盈利）或负（亏损） |
| 提前赎回（全局池） | 全局池不支持提前赎回；比赛独立池在比赛结束前不可退出 |
| 本金清零（Liquidated） | 极端情况下仓位 P&L 亏损超过本金，本金归零，仓位进入 Liquidated 状态 |

## D — 代币模块（v2.0 重构）

| 术语 | 定义 |
|------|------|
| ODD | OddFi 平台代币，BSC BEP-20，总量 1 亿枚（100,000,000），小数位 18 |
| Clean BEP-20 | ODD 合约的形态定义：合约层**零转账税、无单笔上限、无交易冷却、无销毁、无推荐关系存储**；任意 DEX 自由交易；所有税点均在应用层（BettingPool）执行 |
| 下注税 | 用户下注时除筹码之外额外扣的下注税；默认税率 **1% ODD**，运营期可调（上限 3%）；100% 转入推荐人的"推荐奖励累积余额"，无推荐绑定时归平台金库 |
| 派奖税 | 赢家在 BettingPool 领取派彩时扣的派奖税；默认税率 **5% 派彩**，默认按 2pp 质押池 / 1pp 派奖税缓冲（L3）/ 1pp 平台金库 / 1pp 推荐人的比例分配；运营期可动态调整四项比例，但订单一旦 `settle`，其税率与四项比例即被锁定；无推荐绑定时推荐人份额归平台 |
| 推荐奖励累积余额 | `BettingPool` 合约中 `referrerRewardsOdd[referrer]` 的 ODD 累积额；由下注税 1% 与胜单在 `settle` 时锁定给推荐人的派奖份额（默认 1pp）注入；仅可通过推荐人 Claim 取出 |
| 推荐关系 | 链上永久绑定的推荐人-被推荐人关系，**存储位置由 v2.0 前的 ODD.sol 迁至 BettingPool 合约**；仅可绑定一次，不可更改，绑定时机改为"首次 placeBet 前" |
| 无推荐绑定用户 | `referrers[user] == address(0)` 的用户；其下注税 1% 与派奖税中锁定给推荐人的份额全部归平台金库；不影响派奖税其他已配置份额分配 |
| 派奖税缓冲（taxBuffer） | 对赌池 L3 层累积的 ODD，来源为胜单在 `settle` 时锁定给对赌池的派奖份额（默认 1pp）；上限 500,000 ODD；详见 A — 对赌池模块 |
| Claimed | 胜单用户成功执行 `claimPayout(orderId)` 后的终态；净派彩已发放，订单不可再次 Claim |

> **v2.0 废止术语：** ~~买入税（5%）~~、~~卖出利润税（25%）~~、~~成本基准 / costBasis~~、~~持仓均价~~、~~卖出利润~~、~~亏损卖出~~、~~免税白名单~~、~~根节点地址~~、~~卖出冷却~~、~~单笔卖出上限（10%）~~、~~Token Pool 锁仓~~、~~销毁（1pp）~~、~~卖出利润税缓冲~~。
> 若历史文档中仍出现上述术语，以本表 v2.1 重定义或"废止"状态为准。
