## 术语

本文档涉及术语见 docs/product/全局_术语表.md，关键术语如下：

| 术语 | 定义 |
|------|------|
| 最坏亏损（WCL） | 若某方向结果发生，平台净亏损额：`Lᵢ = Pᵢ - Sᵢ - ΣSⱼ` |
| `Sᵢ` | 方向 i 累计 stake 总额 |
| `Pᵢ` | 方向 i 累计应付赔付额；下单成交时按 `Pᵢ += acceptedAmount × lockedOdds` 累加 |
| `lockedOdds` | 每笔注单成交瞬间锁定赔率，后续 Base Odds、压缩或上浮变化均不回算历史注单 |
| 重仓方向 | WCL 最大的方向（即该结果发生时平台亏损最大） |
| 轻仓方向 | WCL 非最大的所有方向 |
| Base Odds | 平台初始赔率，由后端按 §〇 四步法从 Sportmonks 参考赔率生成后写入合约，是动态调整的起点 |
| 外部漂移 | 我方 Base Odds 与 Sportmonks 实时赔率的百分比偏差 |
| 压缩率 r | 对重仓方向赔率执行的折减比例（0%–12%） |
| 上浮系数 k | 当前固定值 1.0（完全对称） |
| 信号灯 | 基于 WCL 的四级风控状态：绿 / 黄 / 橙 / 红 |
| Margin 率 | 当前固定值 10% |

## 〇、开盘赔率生成（Base Odds）

Base Odds 由后端按四步法链下生成，合约只接收并校验最终 Base Odds 数组：

1. `p_implied[i] = 1 / ref_odds[i]`
2. `p_true[i] = p_implied[i] / Σp_implied`
3. `p_adj[i] = p_true[i] × (1 + 10%)`
4. `Base Odds[i] = 1 / p_adj[i]`，按 0.01 步长四舍五入

禁止使用 `Base Odds = ref_odds × (1 - Margin)` 简化公式。链上 `openMarket/updateOdds` 仅验证赔率不低于 1.01 且满足 0.01 tick；Sportmonks 原始赔率、归一化概率和异常告警均由后端完成。

## 一、最坏亏损（WCL）计算

对市场内每个方向 i，计算：

```
Lᵢ = Pᵢ − Sᵢ − ΣSⱼ（j ≠ i）
```

- `Sᵢ`：方向 i 当前总投注额
- `Pᵢ`：方向 i 当前累计应付赔付额，按每笔注单 `acceptedAmount × lockedOdds` 累加
- `ΣSⱼ`：所有其他方向的总投注额之和
- `Lᵢ > 0`：平台亏损；`Lᵢ ≤ 0`：平台盈利

> **V2 说明：** 压缩、上浮、滑点只影响新单的成交 `lockedOdds`。历史注单一旦成交，其 `lockedOdds` 和已累加到 `Pᵢ` 的应付赔付额不因后续赔率变化回算。

**重仓/轻仓判定：**
- 重仓方向 = Lᵢ 最大的方向
- 若多个方向 Lᵢ 相等（并列最大），全部视为重仓，同步压缩；其余方向同步上浮
- 所有方向 Lᵢ ≤ 0 时：不触发压缩，维持 Base Odds

**触发时机：**
- 每笔注单写入后立即重算当场次所有市场的 WCL
- Base Odds 强制更新后重算，但只影响后续新单报价，不回算历史 `Pᵢ`
- AH full push / 退款释放对应 stake 时，同步释放该 stake 对应的 `Pᵢ`

## 二、信号灯四级机制

以 ODD 计量（固定汇率 $0.10/ODD）：

| 状态 | WCL 区间（ODD） | WCL 区间（USD） | 接单状态 |
|------|--------------|--------------|---------|
| 🟢 绿灯 | 0 — 80,000 ODD | $0 — $8,000 | 全额接单，不压缩 |
| 🟡 黄灯 | 80,000 — 180,000 ODD | $8,000 — $18,000 | 全额接单，线性压缩 |
| 🟠 橙灯 | 180,000 — 280,000 ODD | $18,000 — $28,000 | 全额接单，加速压缩 |
| 🔴 红灯 | > 280,000 ODD | > $28,000 | 该方向停止接单 |

**红灯部分成交规则：**
- 新下注请求进行红灯容量检测：按 §7.2 V2 公式反解 `max_stake`
- 可成交部分按 `O_new = max(Base Odds × 0.88, 1.01)` 成交
- 超出部分退回用户余额
- **部分成交为一次性计算**，不做多轮迭代（红灯容量不因赔率变化而动态重算）

## 三、赔率压缩公式（重仓方向）

设 `L` = 重仓方向 WCL（ODD 单位）

**黄灯区间（80,000 < L ≤ 180,000 ODD）：**
```
r = min( (L − 80,000) ÷ 10,000 × 0.4%, 4.0% )
```

**橙灯区间（180,000 < L ≤ 280,000 ODD）：**
```
r = 4.0% + min( (L − 180,000) ÷ 10,000 × 0.8%, 8.0% )
最大值 = 4% + 8% = 12%
```

**压缩后赔率：**
```
重仓新赔率 = Base Odds × (1 − r)
下限保护：不得低于 Base Odds × 0.88（即最大压缩 12%）
若触达下限仍超过红灯阈值 → 触发红灯，停止接单
```

**赔率精度：** 统一保留两位小数，0.01 步长，四舍五入。

> **舍入时机：** 四舍五入仅在**最终对外暴露的赔率值**（重仓压缩后赔率 / 轻仓上浮后赔率 / 滑点折后赔率）上执行一次；压缩率 `r`、上浮率 `r × k`、中间乘积一律按全精度计算，避免每步舍入累积误差导致与链上实际成交价偏离 1 tick 以上。

**赔率下限：** 新赔率不得低于 1.01；低于 1.01 时强制设为 1.01，同时触发红灯告警，等待运营人员处理。

---

## 四、赔率上浮公式（轻仓方向）

```
上浮率     = r × k（k = 1.0，当前固定值）
轻仓新赔率 = Base Odds × (1 + 上浮率)
上限保护   = min(轻仓新赔率, Base Odds × 1.08)
```

**1x2 两个轻仓方向（MVP）：** 两个方向独立执行相同上浮率，不区分各自亏损大小。

## 五、三市场独立原则

1x2、让球（各线独立）、大小球（各线独立）的 WCL 计算和信号灯**完全独立**，不合并、不互相抵消。

### 单场聚合风险信号

在三市场独立计算基础上，额外维护单场聚合风险级别：

| 聚合风险级别 | 触发条件 | 处理方式 |
|------------|---------|---------|
| 正常 | 所有市场绿灯或黄灯 | 无需干预 |
| 提升 | 1 个市场触达橙灯或红灯 | 运营监控，可不介入 |
| 危急 | ≥ 2 个市场触达橙灯或红灯 | 立即触发 Telegram 人工告警 |

> 危急状态不自动暂停接单，是否暂停由运营人员判断后手动操作。

## 六、外部赔率追踪

### 6.1 检测规则

| 参数 | 值 |
|------|---|
| 拉取频率 | 每 5 分钟；开赛前 30 分钟内升至每 1 分钟 |
| 触发阈值 | 任一方向外部漂移 ≥ 5% |
| 覆盖范围 | 所有"待开赛"状态场次的全部市场 |
| 停止时机 | 比赛开始前 5 分钟，停止外部追踪更新 |

**外部漂移计算：**
```
外部漂移(方向i) = | Sportmonks赔率ᵢ − 我方Base Oddsᵢ | ÷ 我方Base Oddsᵢ
```
任一方向漂移 ≥ 5% 即触发整场重新拉取和 Base Odds 更新。

### 6.2 双轨合并计算

Base Odds 强制更新后，赔率按以下顺序重新计算：
1. 新 Base Odds 按 §〇 四步法从 Sportmonks 最新赔率生成
2. 在新 Base Odds 基础上，重新运行信号灯 + 压缩/上浮公式
3. 历史注单 `lockedOdds` 和 `Pᵢ` 不回算，仅影响此后新单成交价

### 6.3 冲突与异常处理

| 场景 | 处理规则 |
|------|---------|
| 更新期间有新下注请求 | 等待 Base Odds 写入完成后再处理，避免使用旧 Base Odds 锁定赔率 |
| Sportmonks 断连 | 保持当前 Base Odds，暂停外部追踪，触发运营告警；最多 15 分钟后人工介入 |
| 赔率变动幅度 ≤ 0.05 | 静默更新，不推送 WebSocket |
| 赔率变动幅度 > 0.05 | 推送 WebSocket，前端赔率实时刷新 |
| 更新后已锁定 Pending 赔率偏差 > 10% | 触发人工审核队列，不自动撤单 |
| 开盘双源赔率偏差 > 3% | 暂缓开盘，触发运营告警；备用源接入前跳过此校验 |

## 七、大额下注滑点机制

### 7.1 触发规则

**MVP 阶段滑点始终开启，无运营端开关。**

| 下注金额 | 处理方式 |
|---------|---------|
| ≤ 10,000 ODD | 无滑点，直接锁定报价赔率成交 |
| > 10,000 ODD | 触发滑点，弹出二次确认弹窗，展示折后赔率 |

### 7.2 折后赔率计算

将本笔注单加入当前 `(Sᵢ, Pᵢ)`，重新运行 WCL + 压缩公式。**计算一次性完成，不做多轮迭代**（与 §二红灯部分成交口径一致：折后赔率锁定后不再因后续 WCL/压缩率变动动态重算）。

**仅计算用户下注方向的压缩赔率作为折后报价；不在折后报价中展示/锁定轻仓方向的上浮赔率**（轻仓上浮按 §四，是本笔注单写入后对其他用户下一笔订单生效的市场状态，不影响本笔成交价）。

**情况一：模拟后未触红灯（WCL ≤ 280,000 ODD）**
- 折后赔率 = 含本笔注单后、在 Base Odds 基础上重算出的压缩赔率（见 §三）
- 全额成交，写入 `Sᵢ += acceptedAmount` 与 `Pᵢ += acceptedAmount × lockedOdds`

**情况二：模拟后触红灯（WCL > 280,000 ODD）**
- `Lᵢ_old` = 本笔注单写入前该方向 WCL
- `O_new = max(Base Odds × 0.88, 1.01)`，按最终赔率 tick 归一化
- 计算最大可接受量：`max_stake = (280,000 - Lᵢ_old) ÷ (O_new - 1)`
- 可成交部分按 `O_new` 写入 `Sᵢ` 和 `Pᵢ`
- 超出部分退回用户余额

### 7.3 前端交互

**全额成交弹窗：**
> "当前下注金额较大，赔率将从 X.XX 调整为 Y.YY，是否确认？"

**部分成交弹窗（触红灯）：**
> "当前市场承载有限，最多可成交 A ODD，赔率 Y.YY，剩余 B ODD 将退回余额，是否确认？"

- 用户确认 → 按上述条件成交
- 用户取消 → 返回下注单，不操作

### 7.4 兜底校验（始终生效，不受滑点影响）

- 每日 VIP 限额
- 单账户单场最高赔付上限 30,000 ODD
- 池子流动性校验（潜在赔付 ≤ BettingPool 可用余额）
- 信号灯红灯停单

## 八、让球市场规则

### 8.1 盘口线

V1 支持十条固定让球线：**-0.25 / -0.5 / -0.75 / -1 / -1.25 / -1.5 / +0 / +0.25 / +0.5 / +0.75**，每条线为独立市场，独立计算 WCL 和信号灯。

V1 不做自动盘口移动（Line Movement）；运营或后端需要开哪条 line，就按 `marketType + line` 创建对应独立 market。

### 8.2 赔率调整

每条线两个方向：**主让赢 / 客让赢**。WCL 公式、重仓/轻仓判定、信号灯阈值、压缩/上浮公式与 1x2 完全相同。

### 8.3 AH 结算场景

AH 支持 full win、full loss、full push、half win、half loss。

**处理流程：**
1. 后端提交最终比分；
2. 合约按 `marketType + line + homeScore + awayScore` 推导 AH 结果；
3. full push：对应注单全额退本金，并同步释放该线两侧 `Sᵢ` 与 `Pᵢ`，不产生派奖税、Margin 或瀑布；
4. half win：50% 本金退回，50% 按锁定赔率进入待 claim；
5. half loss：50% 本金退回，50% 判负进入 `loserStakes`；
6. half 拆分遇到最小单位不可整除时，余数归退回本金。

AH full push 属于正常赛果结算，market 最终为 `Settled`，不是 `Refunded / Cancelled`。

## 九、大小球市场规则

### 9.1 盘口线

V1 支持三条固定大小球线：**1.5 / 2.5 / 3.5**（均为半球线），每条线为独立市场。

### 9.2 赔率调整

每条线两个方向：**大球（Over）/ 小球（Under）**。规则与 1x2、让球完全相同。

### 9.3 无 Push

1.5 / 2.5 / 3.5 均为半球线，总进球数不可能恰好等于 .5，**不存在 Push，无需特殊处理**。

## 十一、全局边界规则

| 场景 | 处理规则 |
|------|---------|
| 所有方向 Lᵢ ≤ 0（平台必赚） | 不触发压缩，维持 Base Odds |
| 多方向 Lᵢ 并列最大 | 全部视为重仓，同步压缩；轻仓方向同步上浮 |
| 压缩后赔率低于 1.01 | 强制设为 1.01，触发红灯告警，等待运营人员处理 |
| 赔率变动 ≤ 0.05 | 静默更新，不推 WebSocket |
| 赔率变动 > 0.05 | 推 WebSocket，前端实时刷新 |
| 比赛开始前 5 分钟 | 锁定所有赔率，停止动态调整，拒绝新投注 |
| 数据源异常（Sportmonks 断连） | 维持最后一次有效赔率，暂停动态调整，触发运营告警 |
