## 正常流程

### 1. 全局池存入

**前置条件：**
- 全局池处于开放存入状态（depositOpen = true）
- 存入金额 ≥ 1,000 ODD
- 用户 ODD 余额充足
- 合约未暂停

**步骤：**
1. 用户选择全局池，选择锁仓档位（7 / 14 / 28 / 60 / 90 天）。
2. 输入存入金额（≥ 1,000 ODD）。
3. 确认风险提示（本金非保本，随赔付结果实时浮动）。
4. ODD 从用户钱包转入做市合约。
5. 系统记录仓位：
   - 存入量、锁仓天数、锁仓乘数
   - 解锁时间 = 存入时间 + 锁仓天数
   - rewardDebt = 当前全局池 rewardPerShare
6. 全局池总存入量 += 存入量。

**全局池锁仓档位与乘数：**

| 档位 | 锁仓天数 | 档位展示乘数 |
|------|---------|---------|
| 短期 | 7 天 | 0.5x |
| 标准 | 14 天 | 1.0x（默认选中） |
| 中期 | 28 天 | 1.8x |
| 较长 | 60 天 | 2.5x |
| 最长 | 90 天 | 3.5x |

**最小存入量：** 1,000 ODD（低于此值拒绝存入）。

---

### 2. 比赛独立池存入

**前置条件：**
- 对应比赛的独立池已开放（比赛创建时自动开放，开赛后自动关闭）
- 存入金额 ≥ 1,000 ODD
- 比赛尚未结算
- 用户 ODD 余额充足

**步骤：**
1. 用户在比赛列表中选择目标比赛，点击存入。
2. 输入存入金额（≥ 1,000 ODD）。
3. 确认风险提示（本金随单场赔付结果浮动，风险集中）。
4. ODD 从用户钱包转入做市合约。
5. 系统记录仓位：
   - 存入量、锁仓乘数固定为 1.0x（无档位选择）
   - 解锁时间 = 该场比赛的预计结束时间
   - rewardDebt = 当前该独立池 rewardPerShare
6. 比赛独立池总存入量 += 存入量。

**说明：**
- 比赛独立池无锁仓档位选择，展示乘数固定为 1.0x。
- 存入后，到比赛结束前无法退出（无提前赎回）。
- 比赛开赛后，独立池停止接受新存入（Deposit 按钮禁用）。

---

### 3. Margin 分配（每场结算后）

**触发时机：** 对赌池完成比赛结算（settle 执行后）。

**分配公式：**

```
本场 Margin = 所有方向总投注额 × 10%
LP 总分 = 本场 Margin × 80%
平台收益 = 本场 Margin × 20%，留在 BettingPool 并记入 platformReserve

全局池总存入 G，本场独立池总存入 M

全局池分得 = LP 总分 × G ÷ (G + M)
独立池分得 = LP 总分 × M ÷ (G + M)

全局池 rewardPerShare += 全局池分得 × 1e18 ÷ G
独立池 rewardPerShare += 独立池分得 × 1e18 ÷ M
```

**重要说明：** Margin 分配与 L2 亏损扣减均以存入本金（不含乘数）为唯一分母基数。当前版本的 `rewardPerShare` 仅按本金总额记账，用户实际 P&L 也仅按本金占比计算。锁仓乘数仅用于档位展示与后续版本扩展，不参与当前版本的实际 Margin 到账或亏损扣减。

**特殊情况：**
- G + M = 0（无 LP）：LP 应得的 80% 自动记入 `platformReserve`，视为协议内合法准备金增量，无需额外调用 `addPlatformReserve`。
- G = 0（全局池为空，只有独立池）：全部 LP 份额归独立池。
- M = 0（无比赛独立池资金，只有全局池）：全部 LP 份额归全局池。

### 4. 平台准备金（防穿仓机制）

**规模：** 平台在对赌/做市相关合约中预存 **15,000,000 ODD** 作为平台准备金（platformReserve），作为四层损失瀑布的 L4 层。

**承担顺序（四层瀑布，单一事实源）：**
本模块不独立定义承担顺序，严格以 `docs/product/对赌池_准备金瀑布_规则设计.md v1.1` 为准：

```
L1 输家下注筹码 → L2 用户 LP 本金（本模块作用点） → L3 taxBuffer（胜单在 `settle` 时锁定给对赌池的份额，默认 1pp，cap 500,000 ODD） → L4 平台准备金（15,000,000 ODD）
```

**本模块在瀑布中的角色：**
- 做市模块的 LP 本金（全局池 G + 比赛独立池 M）在 **L2 层**被按比例扣减（公式见 §5）。
- 本模块**不直接管理**准备金的扣减：L3 taxBuffer 由 BettingPool `claimPayout` 时注入该胜单已锁定给对赌池的份额（默认 1pp）并消耗，L4 platformReserve 由对赌池瀑布合约在 L3 不足时触发。
- 准备金不属于任何 LP 仓位，不参与 Margin 收益分配，不计入 LP 池总存入量（G + M）。
- 由平台多签钱包控制补充，普通用户不可操作。

**每场结算时本模块视角的简化流程：**

```
净亏损 = 获胜方向总毛派奖 - L1 输家下注筹码

若 净亏损 ≤ 0：
    → 无亏损，走 Margin 分配流程（§3）

若 净亏损 > 0：
    → 本模块按 §5 公式计算 LP 应承担部分（最多 G + M），扣减 rewardPerShare
    → 若 LP 本金不足以覆盖：缺口上抛给 L3 / L4，由对赌池瀑布 PRD 规则处置
```

**告警阈值（与对赌池瀑布 PRD 统一）：**
- **emergencyFloor = 100,000 ODD**：准备金跌破此阈值触发熔断，暂停新下注接单；同时由 100,000 ODD 阶梯告警按档触发（共 150 级，瀑布 PRD §5.1 定义）。
- **ReserveTapped 事件（P1）**：L4 准备金首次被触达即触发事件驱动告警（瀑布 PRD §5.2）。
- 本模块不再沿用 v1 "500 万 ODD 告警"/ "10 万 ODD 告警" 两个冲突阈值，统一以瀑布 PRD 为准。

**前端展示：**
- Pools 页面展示准备金余额（Platform Reserve: X,XXX,XXX ODD）及健康状态（绿色 ≥ 1,000,000 ODD / 黄色 ≥ 100,000 ODD / 红色 < emergencyFloor）。
- 准备金不计入用户 APY 计算，仅作风险提示展示。

### 5. 亏损分配（L2 层 LP 本金扣减）

**触发时机：** 单场净亏损 > 0 且 L1 输家筹码不足以覆盖时，进入 L2 层 LP 本金扣减；超出 L2 的部分由 L3 / L4 按瀑布 PRD 规则处置，不在本模块记账。

**L2 分配公式：**

```
L2 应扣减 = min(L1 不足后的剩余亏损, G + M)   ← LP 本金最多归零，不会为负

全局池承担 = L2 应扣减 × G ÷ (G + M)
独立池承担 = L2 应扣减 × M ÷ (G + M)

全局池 rewardPerShare -= 全局池承担 × 1e18 ÷ G
独立池 rewardPerShare -= 独立池承担 × 1e18 ÷ M

若 L2 应扣减 < L1 不足后的剩余亏损：
    → LP 本金全部归零（Liquidated）
    → 剩余缺口 = 剩余亏损 - (G + M) 由 L3 taxBuffer / L4 platformReserve 承担（见对赌池瀑布 PRD §3）
```

**用户个人 P&L：**
```
仓位 P&L = 原始存入 × (当前 rewardPerShare - 仓位 rewardDebt) ÷ 1e18
取回金额 = 原始存入 + P&L（P&L 为负时本金缩减，最低为 0）
```

---

### 6. 申请赎回（requestUnbond）

**前置条件：**
- 仓位处于 Active 状态（未 Unbonding，未已提取）
- 当前时间 ≥ 仓位解锁时间（全局池：到达锁仓到期日；独立池：比赛已结束）

**步骤：**
1. 用户在 Positions 页找到已到期（Ready 状态）仓位，点击 `Request Unbond`（弹出解绑确认弹窗）。
2. 弹窗展示：当前价值、P&L、赎回等待期（约 2-3 天）、将收到金额。
3. 用户确认后，仓位进入 Unbonding 状态。
4. 系统记录 unbondingEpoch = 当前 Epoch 序号。
5. 仓位停止参与后续 Margin 收益分配，也不再承担后续赔付亏损（收益和亏损均以 unbondingEpoch 时点为止）。

**注意：** 点击确认后不可撤回，仓位进入 Unbonding 后无法重新激活。

---

### 7. 提取（withdraw）

**前置条件：**
- 仓位处于 Unbonding 状态，且已完成等待期（前端状态 = Withdrawable）
- 当前 Epoch ≥ unbondingEpoch + 2（已等待 2 个完整 Epoch）

**Epoch 计算规则：**
- 每个 Epoch = 1 天，以 UTC 00:00 为边界。
- 用户在当天任意时刻申请赎回，均等待至下一个 UTC 00:00 才开始计第 1 个 Epoch。
- 等待最长时间：约 3 天（申请当天剩余时间 + 2 个完整 Epoch）。
- 等待最短时间：约 2 天（恰好在 UTC 00:00 申请）。

**步骤：**
1. 用户在 Positions 页找到已 Withdrawable 仓位，点击 Withdraw。
2. 计算最终 P&L = 原始存入 × (rewardPerShare - rewardDebt) ÷ 1e18（此值在 Unbonding 时已冻结，不再变化）。
3. 计算取回金额：
   - P&L ≥ 0：取回 = 原始存入 + P&L。
   - P&L < 0：取回 = max(0, 原始存入 - |P&L|)（本金可能缩水至 0）。
4. ODD 转入用户钱包。
5. 仓位状态更新为 Withdrawn，全局池/独立池总存入量 -= 原始存入量。

---

### 8. 提前赎回规则

| 池子类型 | 提前赎回 | 说明 |
|---------|---------|------|
| 全局池 | 不支持 | 锁仓期内无任何退出路径，Locked 按钮禁用 |
| 比赛独立池 | 不支持（比赛结束前） | 比赛结束后方可申请赎回，进入正常流程 |

**例外：无例外。** 全局池锁定期内任何情况均不可退出。

## 异常流程

| 场景 | 触发条件 | 处理方式 |
|------|---------|---------|
| 存入金额 < 1,000 ODD | 提交时校验失败 | Toast 提示"Minimum deposit is 1,000 ODD"，不提交链上 |
| 钱包余额不足 | 输入金额 > 余额 | 输入框红色描边，Confirm 按钮禁用 |
| 比赛已开赛，尝试存入独立池 | depositOpen = false | 按钮禁用，提示"Match started" |
| 比赛已结束但未结算，尝试存入 | pool.settled = false 但 depositOpen = false | 按钮禁用，提示"Pending settlement" |
| Unbonding 期间 P&L 变化 | 已在 requestUnbond 时冻结 reward/loss 快照 | 当前实现已收口 |
| 本金归零（P&L 亏损超本金） | P&L < -原始存入 | 取回金额 = 0，仓位显示"Liquidated"状态，无法操作 |
| 合约暂停 | Owner 调用 pause | 存入/提取失败，等待 unpause |
| 准备金跌破 emergencyFloor（100,000 ODD） | 极端亏损多次击穿 L3 | 熔断暂停新下注接单；触发 P1 告警；按对赌池瀑布 PRD §5 处置 |
| 准备金阶梯告警（每 100,000 ODD 一档） | 准备金余额下降穿越阶梯点 | 触发 P2 阶梯告警（运营通道），对赌池瀑布 PRD §5.1 共 150 级 |
| ReserveTapped 事件（L4 首次被触达） | 本场结算触发 L4 准备金扣减 | 事件驱动 P1 告警，运营即时评估 |
| LP 本金归零（L2 耗尽） | L2 全部扣至 0，缺口抛给 L3/L4 | 仓位状态 Liquidated；缺口按瀑布 PRD 处置 |
| LP + L3 + L4 均不足以覆盖赔付 | 极端穿仓且 emergencyFloor 以下 | 熔断触发，暂停接单；链下补充资金后重试结算 |

## 边界条件

| 边界 | 规则 |
|------|------|
| 最小存入量 | 1,000 ODD，低于此值拒绝 |
| Epoch 计算 | 当前 Epoch = (block.timestamp - epochStart) ÷ 86400，整数除法 |
| 赎回等待期 | 2 个完整 Epoch，最短约 2 天，最长约 3 天 |
| G + M = 0 时 Margin 分配 | LP 应得 80% 自动记入 `platformReserve`，不报错 |
| 本金归零后的状态 | 显示 Liquidated，无法操作，无法恢复 |
| 独立池比赛结束后新存入 | 严格拒绝（depositOpen = false） |
| 全局池与独立池仓位可以并存 | 同一用户可同时在全局池和多个独立池持有仓位 |
| 比赛独立池乘数 | 固定 1.0x，无法自定义（合约层校验，传错值会被拒绝） |
| 状态流转 | `Active → Ready → Unbonding → Withdrawable → Withdrawn`；`Liquidated` 为终态 |

## 当前限制

1. **Unbonding 期间收益冻结已实现：** 当前合约在 `requestUnbond` 时冻结 reward/loss 快照，Unbonding 后不再继续累积新的收益或亏损。
2. **epochStart 初始化偏差：** 合约以部署时间取整（当天 UTC 00:00），若部署时间非恰好 00:00，第一个 Epoch 略短。部署时由运营核对 UTC 时间，可接受低优先级风险。
3. **独立池乘数固定 1.0x：** 当前 Match Pool 不再从外部传入倍率参数，合约内部固定使用 1.0x，不存在传错值的问题。
4. **全局池无提前赎回：** 锁定期内任何情况下均无退出路径。用户存入前须知晓。
5. **v2 联动：L3 taxBuffer 冷启动填充慢：** 胜单在 `settle` 时锁定给对赌池的默认份额仅 1pp，注入速率相对 v1（卖出税 4pp）显著下降，taxBufferCap 500,000 ODD 冷启动期可能长期未填满。L2 耗尽时缺口将更快抛给 L4。内测两周后由运营复评 cap。
6. **四层瀑布已落地，但参数仍需持续监控：** 当前合约已实现 `taxBuffer / lpLossOffsetRemaining / ReserveTapped / ReserveStepAlert / emergencyFloor`，后续仍需根据真实消耗速率复评阈值与补仓策略。
