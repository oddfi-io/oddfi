## 正常流程

### 1. 市场开盘

**触发条件：** 比赛信息从 Sportmonks 拉取，后端确认赔率有效。

**步骤：**
1. 平台 Owner 创建市场，设定 matchId、比赛结束时间、方向数量（2 或 3）。
2. 系统按 `赔率_规则设计.md §〇` 四步法从 Sportmonks 原始赔率生成 Base Odds，写入 Redis/链上；禁止使用 `refOdds × (1 - Margin)` 简化公式。
3. 全局池和比赛独立池同步开放存入。
4. 初始信号灯均为绿灯（WCL = 0）。

**异常：** 若两个数据源开盘赔率偏差 > 3%，暂缓开盘，触发运营告警，等待人工确认。备用数据源接入前跳过此校验。

---

### 2. 外部赔率追踪（持续后台运行）

**触发条件：** Go 后端独立协程，每 5 分钟执行（开赛前 30 分钟内升为每 1 分钟）。

**步骤：**
1. 后端拉取 Sportmonks 实时赔率。
2. 计算各方向外部漂移 = |Sportmonks 赔率 - 我方 Base Odds| ÷ 我方 Base Odds。
3. 若任一方向漂移 ≥ 5%：
   a. 按 `赔率_规则设计.md §〇` 四步法生成新 Base Odds。
   b. 在新 Base Odds 基础上，重新运行信号灯 + 压缩/上浮公式。
   c. 将结果写入 Redis。
   d. 若最终赔率变动 > 0.05，推送 WebSocket 更新前端。
4. 若漂移 < 5%，静默不触发。

**停止条件：** 后端调用链上手动封锁后停止外部追踪更新，保持锁定赔率；若未手动封锁，则可持续更新到比赛结束前。

**Sportmonks 断连处理：** 维持当前 Base Odds，暂停外部追踪，触发 Telegram 运营告警，最多持续 15 分钟后人工介入。

**更新期间有新下注请求：** 队列等待，Base Odds 写入完成后再处理。

---

### 3. 用户下注流程

**前置条件：**
- 市场处于开放状态（open=true，未结算）
- 当前时间 < 比赛结束时间
- market 未被后端手动封锁
- 用户 ODD 余额足够

**六项校验（Remy 后端执行，顺序不可颠倒）：**

| 校验项 | 规则 | 失败返回 |
|-------|------|---------|
| 每日 VIP 限额 | 当日累计下注量 + 本次下注 ≤ VIP 等级对应限额（UTC 00:00 重置） | DAILY_LIMIT_EXCEEDED |
| 未平仓上限 | 当前未平仓总额 + 本次下注 ≤ max(5,000 ODD, 有效质押量) | OPEN_POSITION_EXCEEDED |
| 单账户单场赔付上限 | 本次注单潜在赔付 + 已有未平仓 ≤ 30,000 ODD | PAYOUT_LIMIT_EXCEEDED |
| 池子流动性 | 潜在赔付 ≤ BettingPool 可用承担能力（L1 输家筹码 + L2 用户 LP + L3 taxBuffer + L4 平台准备金，按 `对赌池_准备金瀑布_规则设计.md` 顺序） | POOL_INSUFFICIENT |
| 信号灯预检 | 调用 previewSignal（赔率参数由后端从 Redis 实时读取），若成交后触达红灯则计算部分成交量 | MARKET_CLOSED（若容量=0） |
| 赔率时效 | 成交赔率与当前 Redis 赔率偏差 ≤ 0.05（偏差超出拒绝成交） | ODDS_STALE |

**滑点处理（始终开启）：**
- 注单 ≤ 10,000 ODD：无滑点，直接按报价赔率成交。
- 注单 > 10,000 ODD：预算折后赔率，前端弹出二次确认弹窗，展示折后赔率。
  - 用户确认 → 按折后赔率成交（若触达红灯，则执行部分成交）。
  - 用户取消 → 不成交，不操作。

**部分成交规则（触达红灯）：**
- 最大可成交量按 `docs/product/赔率_规则设计.md §7.2` 的红灯容量公式一次性计算：`max_stake = (280,000 - Lᵢ_old) ÷ (O_new - 1)`，其中 `O_new = max(Base Odds × 0.88, 1.01)`。
- 成交量 = `min(注单金额, max_stake)`。
- 超出部分原路退回用户余额，同时展示告知文案。
- 若 `max_stake <= 0`，返回 `MARKET_CLOSED`，不成交。

**说明：** previewSignal 的返回值为预算值，从用户确认到提交链上期间，市场状态可能已变化（其他用户抢先下注）。实际成交金额以链上执行结果为准，前端应展示实际成交结果（通过 BetPlaced / BetPartialFilled 事件），而非仅展示 previewSignal 的预算结果。

**成交后操作（链上）：**
1. 记录注单（betId、用户、市场、方向、金额、赔率、状态=Pending）。
2. 更新该方向 `totalStakedByOutcome/Sᵢ` 与 `payoutByOutcome/Pᵢ`，其中 `Pᵢ += acceptedAmount × lockedOdds`。
3. 更新用户未平仓金额。
4. 重算 WCL，更新信号灯。
5. 若赔率变动 > 0.05，推送 WebSocket。

### 4. 赔率动态调整

**重仓/轻仓判定：**
- 对每个方向计算 `WCL = Pᵢ − Sᵢ − ΣSⱼ（j ≠ i）`，其中 `Pᵢ` 来自逐笔成交 `lockedOdds` 累加。
- WCL 最大的方向为重仓方向，其余为轻仓方向。
- 若所有方向 WCL ≤ 0，不触发压缩，维持 Base Odds。
- 若多个方向 WCL 相等（并列最大），全部视为重仓，同步压缩。

**压缩率计算（重仓方向）：**

| 信号灯 | WCL 范围（ODD） | 压缩率公式 |
|-------|--------------|----------|
| 绿灯 | 0 — 80,000 | 不压缩，r = 0 |
| 黄灯 | 80,000 — 180,000 | r = (WCL - 80,000) ÷ 10,000 × 0.4%，最大 4.0% |
| 橙灯 | 180,000 — 280,000 | r = 4.0% + (WCL - 180,000) ÷ 10,000 × 0.8%，最大 12.0% |
| 红灯 | ≥ 280,000 | 停止接单，不计算 r |

**重仓新赔率 = Base Odds × (1 - r)**，不得低于 Base Odds × 0.88。

**上浮（轻仓方向）：**
- 上浮率 = r × 1.0（k 固定为 1.0）。
- 轻仓新赔率 = Base Odds × (1 + 上浮率)。
- 上限：不超过 Base Odds × 1.08（防套利）。
- MVP 阶段：1x2 的两个轻仓方向均统一上浮，不区分各自敞口差异。

**赔率精度：** 统一保留两位小数，步长 0.01，四舍五入。

**赔率变动推送规则：**
- 变动 ≤ 0.05：静默更新 Redis，不推 WebSocket。
- 变动 > 0.05：推送 WebSocket，前端实时刷新。

**赔率下限保护：** 若调整后赔率低于 1.01，强制设为 1.01，触发红灯告警，等待人工处理。

### 5. 三市场独立计算原则

1x2、让球（-0.25/-0.5/-0.75/-1/-1.25/-1.5/+0/+0.25/+0.5/+0.75）、大小球（1.5/2.5/3.5）三类市场，各市场内每条线均为独立 MarketState，互不干扰：
- WCL 独立计算
- 信号灯独立触发
- 赔率独立调整
- 赔付独立结算

**单场聚合风险信号：**

| 级别 | 触发条件 | 处理方式 |
|------|---------|---------|
| 正常 | 所有市场绿灯或黄灯 | 无需干预 |
| 提升 | 1 个市场触达橙灯或红灯 | 运营监控，可不介入 |
| 危急 | 2 个及以上市场触达橙灯或红灯 | 立即触发 Telegram 人工介入告警 |

危急状态不自动暂停接单，是否暂停由运营人员手动判断并操作。

### 6. AH Push / 半赢 / 半输流程

**触发条件：** AH line 根据最终比分出现 full push、half win 或 half loss。

**流程：**
1. Remy 后端接收双源赛果并提交最终比分。
2. Remy 按分页读取 betIds，调用 `settleMarketBetsByScore(marketId, homeScore, awayScore, betIds)` 分批结算。
3. 合约根据 `marketType + line + homeScore + awayScore` 推导每笔注单结果：
   a. full push：本金全额退回，注单为 `Refunded`，该注单对应 `Sᵢ` 与 `Pᵢ` 全额释放。
   b. half win：一半本金退回并释放对应 `Sᵢ/Pᵢ`，一半本金按锁定赔率进入待 claim。
   c. half loss：一半本金退回并释放对应 `Sᵢ/Pᵢ`，一半本金判负。
4. 所有 bet 分批处理完成后，Remy 调用 `finalizeMarketSettlement(marketId, 0)`，market 进入 `Settled`。
5. 用户收到的退款可立即用于新下注；中奖 half 的 claim 仍需用户后续 `claimPayout`。

**边界说明：**
- full push 是有赛果的正常结算，market 最终为 `Settled`，不是 `Refunded / Cancelled`。
- half 拆分遇到最小单位不可整除时，余数归退回本金。
- 大小球 1.5/2.5/3.5 均为半球线，不存在 Push。

### 6A. Cash Out 提前关闭流程

**触发条件：** 用户在 market 仍为 `Open` 且比赛未结束前，对自己名下 `Pending` 注单主动撤出。

**流程：**
1. 前端读取 bet、market 和当前 odds，按当前 `quotedOdds` 计算可返还金额。
2. 用户确认后调用 `cashOut(betId, expectedQuoteVersion, quotedAt, minAmountOut, deadline)`。
3. 合约校验 bet owner、`Pending` 状态、market 为 `Open`、未到 `matchEndTime`、quote guard 未过期。
4. 若 market 已被后端手动 `lockMarket` 封锁为 `Locked`，Cash Out 失败，用户只能等待最终结算或退款。
5. 合约按 `remainingStake * lockedOdds / currentOdds * (1 - feeBps)` 计算返还额：距离开赛超过 30 分钟收 10%，否则收 20%。
6. 成功后 bet 进入 `CashedOut` 终态，释放该注单对应的市场暴露和用户未结算风险。
7. 若返还额低于剩余本金，差额进入平台准备金；若返还额高于剩余本金，超出部分按现有瀑布承担。

**边界说明：**
- Cash Out 是提前终态，不是退款；不会把 `refundedAmount` 伪写为本金。
- Cash Out 不回滚用户当日下注限额，避免反复下注和撤出绕过 VIP 限额。
- 已 Cash Out 注单不再参与比分结算、退款或胜单 Claim。
- 若某 market 全部注单都已 Cash Out，Remy 仍应在赛后提交一次空 betIds 的比分结算记录比分，再 finalize。

---

### 7. 结算流程

**触发条件：** 比赛结束，双源赛果核实一致，多签执行 settle。

**步骤：**
1. 后端双源（Sportmonks 主 + 备用源）核实结果，生成 calldata，提交多签。
2. 多签分批调用 `settleMarketBetsByScore(marketId, homeScore, awayScore, betIds)`，再调用 `finalizeMarketSettlement(marketId, 0)`。
3. 计算总 Margin = 扣除 push/refund 后实际参与 win/loss 结算的投注总额 × 10%。
4. Margin 的 80% 按全局池与独立池存入比例分配给 LP（见做市模块），20% 归平台并留在 BettingPool 记入 `platformReserve`。
5. 获胜本金：计算毛派奖 = winStake × 赔率，状态更新为 Won（待 Claim），并记录 `claimablePayout`，同时锁定该订单的派奖税率快照、四项分配比例快照，以及推荐关系快照。
6. 落败本金：状态更新为 Lost，投注额留在合约。
7. 结算时按毛派奖口径计算赔付缺口：若获胜方向总毛派奖 > 落败方向总投注（L1），按 `对赌池_准备金瀑布_规则设计.md` 四层瀑布顺序（L1 → L2 用户 LP → L3 taxBuffer → L4 平台准备金）依次扣减，任一 L4 扣减触发 ReserveTapped 告警。
8. 市场标记为已结算（settled=true，open=false），停止比赛独立池存入；获胜用户后续通过 `claimPayout(orderId)` 领取净派彩，派奖税也在 Claim 时按该订单已锁定的税率/比例快照扣除和分配。

**胜单 Claim 状态流转：**
- `Pending` → `Won（待 Claim）`：`settle` 确认该订单获胜。
- `Won（待 Claim）` → `Claimed`：用户成功执行 `claimPayout(orderId)`，净派彩已转出，订单终态关闭。
- `Claimed` 为终态；不允许重复 Claim。
- 胜单 **不设置 Claim 期限**；只要订单处于 `Won（待 Claim）`，用户可在任意未来时间发起 Claim。

## 异常流程

| 场景 | 触发条件 | 处理方式 |
|------|---------|---------|
| 市场已结算，用户尝试下注 | market.settled = true | 返回 MARKET_CLOSED |
| 后端已手动封锁 market，用户尝试下注 | market.status = Locked | 返回 MARKET_LOCKED |
| 后端已手动封锁 market，用户尝试 Cash Out | market.status = Locked | 返回 MARKET_LOCKED，用户等待最终结算或退款 |
| 比赛已结束，用户尝试下注 | block.timestamp ≥ matchEndTime | 返回 MARKET_CLOSED |
| 比赛已结束，用户尝试 Cash Out | block.timestamp ≥ matchEndTime | 返回 MARKET_CLOSED，等待结算路径 |
| 方向已触达红灯（容量=0） | 容量 = 0 | 返回 MARKET_CLOSED，不成交 |
| 赔率已过期（偏差 > 0.05） | Redis 赔率已更新但前端未刷新 | 拒绝成交，返回 ODDS_STALE，前端推最新赔率 |
| Pending bet 赔率与新赔率偏差 > 10% | Base Odds 更新后 | 触发人工审核队列，不自动撤单 |
| 用户余额不足 | 钱包 ODD < 下注金额 | 前端拦截，不提交链上 |
| 合约暂停（Paused） | Owner 调用 pause | 所有下注请求返回失败，不结算 |
| 用户对未结算 / 非胜单 / 已退款订单调用 claimPayout | 订单状态不是 `Won（待 Claim）` | revert `BettingPool: payout not claimable` |
| 用户对已 Cash Out 注单再次 Cash Out、退款或 Claim | 订单状态为 `CashedOut` | revert，订单已终态关闭 |
| claimPayout 时合约可用 ODD 余额不足 | 极端亏损场景，用户发起 Claim 时转账失败 | 本次 `claimPayout` revert，订单保持 `Won（待 Claim）`；待平台补足后用户重试；已结算市场状态不回退 |
| 用户对已 Claimed 胜单再次调用 claimPayout | 订单已处于终态 | revert `BettingPool: payout already claimed` |

## 边界条件

| 边界 | 规则 |
|------|------|
| 每日 VIP 限额 | UTC 00:00 重置，重置前余额不累计到次日 |
| 最小下注 | **100 ODD**（合约层 `BettingPool.placeBet` 强制 `require(amount >= 100e18)`，详见代币模块 §2）；前端输入校验同步拦截；信号灯机制在此之上另行控制（容量 = 0 时拒绝） |
| 最小 Cash Out 返还 | **10 ODD**；低于该金额的提前关闭请求失败 |
| 最大赔率压缩 | 12%，压缩至此仍超红灯阈值时改为停止接单 |
| 最大轻仓上浮 | 8%，超过时截断 |
| 赔率精度 | 两位小数，步长 0.01 |
| 赔率绝对下限 | 1.01（含压缩后低于此值时强制设置并告警） |
| 串关总赔率上限 | ×200，超出自动截断 |
| 单张串关最高赔付 | 30,000 ODD，超出部分不赔付，投注前告知用户 |
| 串关最大腿数 | 6串1（MVP 阶段） |

## 当前限制

1. **AH 扩盘口已实现：** AH 已扩展到十条固定 line，full push / half win / half loss 统一由比分结算处理；旧 `pushRefundMarket` 已删除。
2. **备用数据源未接入：** 开盘双源偏差 > 3% 的校验暂时跳过，主源断连仅靠告警，无自动切换。
3. **红灯部分成交后赔率变化（H4）：** 产品决策为一次性计算（不循环），轻微低估最大可成交量，已知可接受偏差。
4. **v2 联动：L3 taxBuffer 冷启动填充慢：** 派奖税中分配给对赌池的锁定默认份额仅 1pp，注入速率低于 v1 卖出税 4pp；流水起量前 L3 可能长期空置；L4 兜底不受影响。内测两周后由产品/运营复评 taxBufferCap。
5. **Cash Out 与串关已在测试网升级：** 当前 BSC Testnet 已支持 `cashOut`、`placeParlay / settleParlay / claimParlayPayout`；串关不支持提前 Cash Out，进行中展示估值使用 `BettingParlayLens.estimateParlayValue`。
