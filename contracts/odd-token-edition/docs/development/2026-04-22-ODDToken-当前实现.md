# ODDToken 当前实现

**状态：** 开发中，锁仓与来源账本 Phase 1/2 + 配套合约主干 + 既有业务最小接入已本地实现
**日期：** 2026-06-12
**基线：** 当前 `src/modules/token/ODDToken.sol`、`src/modules/token/interfaces/IODDTokenBusiness.sol`

## 1. 模块定位

`ODDToken` 已从“纯 ERC20 底座”扩展为 ODD 发售、锁仓、来源账本和业务净盈亏登记的核心合约。

当前职责：

1. ERC20 / BEP-20 兼容余额、授权、转账；
2. pause / unpause；
3. UUPS 升级权限控制；
4. 固定总量初始化与五类来源初始分配；
5. sale / reward / business locked 来源账本；
6. 销售 29 天阶梯解锁、奖励 180 天线性解锁；
7. 白名单业务合约的用户入金快照、出金登记、亏损确认和净盈利可转；
8. DEX launch 与业务净盈利 swap 的一次性 `transferFrom` 放行；
9. sale cancel/refund 时由 TierSale 收回用户仍可交回的销售来源 ODD。

仍不承载：

- 交易税；
- 黑名单；
- 推荐关系本身；
- 赔率、结算、LP 瀑布、staking 奖励公式；
- 管理员任意转移用户余额。

## 2. 初始化与角色

### `initialize(address adminTimelock, address pauser)`

初始化只允许通过 proxy 调用一次。

规则：

- `adminTimelock` 和 `pauser` 均不得为零地址；
- 初始化 ERC20、Pausable、AccessControl；
- 将 `TokenConstants.TOTAL_SUPPLY` 铸造到 `address(this)`，不再铸造给 admin；
- `adminTimelock` 获得：
  - `DEFAULT_ADMIN_ROLE`
  - `UPGRADER_ROLE`
  - `WHITELIST_ADMIN_ROLE`
  - `HOUSEVAULT_MANAGER_ROLE`
  - `DEX_LAUNCHER_ROLE`
  - `SALE_ADMIN_ROLE`
  - `REWARD_DISTRIBUTOR_ROLE`
- `pauser` 获得 `PAUSER_ROLE`。

事件：

- `TokenInitialized(adminTimelock, pauser, totalSupply)`

## 3. 固定来源与初始分配

固定来源结构：

```solidity
struct FixedSources {
    address tierSale;
    address houseVault;
    address dexLaunchController;
    address ecosystemRewards;
    address opsTreasury;
}
```

治理配置入口：

- `setFixedSourceContracts(FixedSources calldata sources)`：只能配置一次，前四类来源必须是合约地址，`opsTreasury` 必须非零；
- `setTreasurySink(address account, bool allowed)`：登记 treasury sink；
- `setWhitelist(address account, bool allowed)`：登记业务白名单，禁止 EOA 和 DEX restricted target；
- `setDexRestrictedTarget(address account, bool restricted)`：登记 Router、PositionManager、V3 Pool、聚合器等 DEX 限制目标；
- `allocateInitialSupply()`：只能执行一次，并要求 `opsTreasury` 已登记为 treasury sink。

初始分配：

| 接收方 | 数量 |
| --- | ---: |
| TierSale | `30,000,000 ether` |
| HouseVault | `25,000,000 ether` |
| DexLaunchController | `10,000,000 ether` |
| EcosystemRewards | `15,000,000 ether` |
| OpsTreasury | `20,000,000 ether` |

`allocateInitialSupply()` 执行后，`dexLiquidityTransferableAllocation` 初始化为 `10,000,000 ether`，供 Pancake V3 launch 受控消耗。

## 4. 来源账本

账户来源结构：

```solidity
struct SourceAccount {
    uint256 salePrincipalRemaining;
    uint256 rewardPrincipalRemaining;
    uint256 businessLockedRemaining;
}
```

对外拆分结构：

```solidity
struct SourceBreakdown {
    uint256 saleLocked;
    uint256 rewardLocked;
    uint256 businessLocked;
    uint256 transferable;
}
```

当前实现中：

- `salePrincipalRemaining` 是销售来源剩余本金，当前锁定量由 `poolLaunchTime` 和 29 天曲线动态计算；
- `rewardPrincipalRemaining` 是奖励来源剩余本金，当前锁定量由 `poolLaunchTime` 和 180 天曲线动态计算；
- `businessLockedRemaining` 当前仅作为保守锁定/兼容桶保留；
- `sourceBalanceOf(account)` 返回当前锁定拆分和可转余额；
- `transferableBalanceOf(account) = balanceOf(account) - lockedBalanceOf(account)`。

已知后续接入注意点：

- 业务合约接入前，需要继续验证“部分解锁 sale/reward 来源被业务消耗后”的边界，确保亏损只扣当前仍锁定的来源，不多锁用户可转余额；
- 当前 Phase 1 单测覆盖全锁定来源、净盈利可转、全亏损确认、DEX launch 和业务净盈利 swap 主路径。

## 5. 发售与奖励发放

### `distributeSalePurchase(address user, uint256 amount)`

- 只能由 `fixedSources.tierSale` 调用；
- 从 TierSale 转 ODD 给用户；
- 增加用户 `salePrincipalRemaining`；
- 事件：`SalePurchaseDistributed(user, amount)`。

### `reclaimSalePurchase(address user, uint256 amount)`

- 只能由 `fixedSources.tierSale` 调用；
- 用于 sale cancel/refund；
- 要求用户已授权 TierSale 足够 ODD，且 `salePrincipalRemaining >= amount`；
- 扣减用户销售来源账本，并把 ODD 从用户转回 TierSale；
- 事件：`SalePurchaseReclaimed(user, amount)`。

### `distributeRewardClaim(address user, uint256 amount)`

- 只能由 `fixedSources.ecosystemRewards` 调用；
- 从 EcosystemRewards 转 ODD 给用户；
- 增加用户 `rewardPrincipalRemaining`；
- 事件：`RewardClaimDistributed(user, amount)`。

## 6. 业务来源快照

业务快照结构：

```solidity
struct BusinessSnapshot {
    address user;
    address businessContract;
    uint16 businessType;
    bytes32 rawId;
    uint64 createdAt;
    uint64 finalizedAt;
    uint256 businessIn;
    uint256 totalBusinessOut;
    uint256 principalReturned;
    uint256 profitRecognized;
    uint256 lossRecognized;
    bool finalized;
    SourceBreakdown sourceIn;
}
```

### `consumeBusinessInflow(address user, uint16 businessType, bytes32 rawId, uint256 amount)`

- 只能由 `whitelist[msg.sender] == true` 的业务合约调用；
- `businessId = keccak256(abi.encode(msg.sender, businessType, rawId))`；
- 同一 `businessId` 不得重复；
- 消耗用户 allowance；
- 按 `businessLocked -> sale -> reward -> transferable` 生成来源快照；
- 内部把 ODD 从用户转入业务合约；
- 返回 `businessId`。

### `registerBusinessOutcomeDelta(address user, bytes32 businessId, uint256 businessOutDelta, bool finalized)`

- 只能由创建 snapshot 的业务合约调用；
- 累计 `totalBusinessOut`；
- 按累计本金回款比例恢复原来源；
- 超过 `businessIn` 的部分确认为净盈利，不新增锁定来源；
- `businessOutDelta == 0 && finalized == true` 用于确认全亏损；
- finalized 后不能再次登记 outcome；
- 内部从业务合约转账给用户。

### `registerBusinessProfitAndTransfer(...)`

- 用于无用户本金入金的业务净收益；
- 当前目标路径是 ODD 推荐奖励 claim；
- 直接从白名单业务合约转 ODD 给用户；
- 不增加用户锁定来源。

### `registerBusinessProfitForDexSwap(...)`

- 用于业务净收益直接走 Pancake V3 swap；
- `routerOrSpender` 与 `expectedPoolOrTarget` 必须已登记为 `dexRestrictedTarget`；
- 记录一次性 `businessProfitSwapAllowance[from][routerOrSpender][expectedPoolOrTarget]`；
- 后续 `transferFrom` 只有匹配 `from / msg.sender / to` 时才放行；
- 用于覆盖 `claimUSDTReferralRewards`，不允许变成通用 DEX 绕过入口。

## 7. 转账限制

普通 `transfer / transferFrom` 必须经过 `_enforceTransferRules`：

- pause 时所有转账、burn 和业务入口停止；
- 普通用户不能直接转入白名单业务合约；
- 白名单业务合约不能普通转账给用户，必须使用业务 outcome / profit 接口；
- TierSale / EcosystemRewards 不能普通转给非 treasury sink；
- HouseVault 只能普通转给白名单或 treasury sink；
- DexLaunchController 只能普通转回 treasury sink，建池走一次性受控 `transferFrom`；
- 普通用户转账数量不得超过 `transferableBalanceOf(user)`；
- treasury sink 向外转账按平台自有可转余额处理。

受控内部转账使用短生命周期 `TransferContext`，只在 Token 自己的发放、业务登记、初始分配、DEX launch 或业务净盈利 swap 过程中打开，完成后恢复为 `None`。

## 8. DEX Launch

治理入口：

- `setDexLaunchTransferTarget(address spender, address pool)`：配置 Pancake V3 NonfungiblePositionManager 与目标 V3 Pool；
- `markDexPoolLaunched(uint64 launchTime)`：只能由 `DEX_LAUNCHER_ROLE` 调用一次，设置全局 `poolLaunchTime`。

`transferFrom` 识别：

- `from == fixedSources.dexLaunchController`
- `msg.sender == dexLaunchSpender`
- `to == dexLaunchPool`
- `value <= dexLiquidityTransferableAllocation`

满足时扣减 `dexLiquidityTransferableAllocation` 并放行建池拉币。

## 9. Burn

`burn(uint256 amount)`：

- 用户只能销毁自己的 ODD；
- `amount > 0`；
- pause 时失败；
- `nonReentrant`；
- 按来源顺序同步扣减账本；
- 事件：`SourceBurned(account, amount, sourceBurned)`。

## 11. 配套合约当前本地实现

### `TierSale`

- 10 档销售，每档 `3,000,000 ODD`；
- 第 N 档价格为 `N * 0.01 USDT`，按 USDT `decimals()` 换算；
- `buy` 支持跨档计价，收 USDT 后调用 `distributeSalePurchase` 登记 sale 来源；
- `cancelSale` 后用户可调用 `refundPurchase(purchaseId, oddAmount)`，通过 `reclaimSalePurchase` 交回对应 sale ODD 后按该笔购买价格退款；
- `forceFinalize` 记录参与建池的 USDT/ODD 数量，`approveLaunch` 只在 soldOut 或 forceFinalized 后开放给 DexLaunchController。

### `EcosystemRewards`

- 管理员配置类别预算；
- `REWARD_DISTRIBUTOR_ROLE` 创建或取消用户 claimable；
- 用户 `claim(claimId)` 后调用 `distributeRewardClaim`，把奖励登记为 reward 来源。

### `HouseVault`

- 持有 25% 储备；
- `transferOdd(to, amount)` 只允许 `HOUSEVAULT_MANAGER_ROLE` 调用；
- 目标必须是 ODDToken 白名单业务合约或 treasury sink，且不得是 DEX restricted target。
- `fundBettingPlatformReserve(bettingPool, amount)` 只允许 `HOUSEVAULT_MANAGER_ROLE` 调用，专用于通过 `BettingPool.addPlatformReserve` 注入 L4 `platformReserve / accountedBalance`；
- 普通 `transferOdd(BettingPool, amount)` 不会增加 L4 账本，只作为普通治理划转。

### `DexLaunchController`

- 只使用 PancakeSwap V3 `NonfungiblePositionManager` 创建或复用 ODD/USDT pool；
- launch 前校验 TierSale 已 approve launch，且使用数量不超过批准额度；
- launch 时登记 PositionManager 和 V3 pool 为 `dexRestrictedTarget`，配置 Token 的 DEX launch 一次性拉币目标；
- mint LP NFT 到 `DexLpLocker`，记录 `pool / lpTokenId / liquidity / oddUsed / usdtUsed / launchTime`；
- 成功后调用 `ODDToken.markDexPoolLaunched` 启动 sale/reward 解锁曲线；
- `sweepRemainder` 在 launch 后开放，ODD 只能扫回 treasury sink。

### `DexLpLocker`

- 接收 PancakeSwap V3 LP NFT / position token；
- `lockPosition(tokenId,unlockAt)` 只允许 `DEX_LAUNCHER_ROLE` 调用，要求 locker 当前持有该 tokenId；
- `releasePosition(tokenId,to)` 只允许 `DEX_LAUNCHER_ROLE` 调用，且必须在 `block.timestamp >= unlockAt` 后；
- 当前配套测试覆盖 launch 后 NFT owner 为 locker、未到期释放失败、到期释放成功。
