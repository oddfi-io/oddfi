# 手动封锁市场实施方案

**状态：** 已实现，本地验证通过
**日期：** 2026-06-02
**关联架构：** `docs/architecture/oddfi-mvp-总体架构.md`、`docs/architecture/2026-04-23-BettingSettlementModule-架构方案.md`

## 1. 目标

移除当前“开赛前 5 分钟自动锁盘”的下注限制，改为：

- market 默认保持 `Open`，只要当前时间未到 `matchEndTime`，用户就可以下注；
- 后端/运营可在比赛结束前主动调用手动封锁方法，将指定 market 置为 `Locked`；
- market 被手动封锁后，`previewSignal / placeBet / updateOdds` 均不可继续执行；
- 即使后端从未手动封锁，比赛结束后仍可正常调用 `settleMarketBetsByScore -> finalizeMarketSettlement(marketId,0)` 完成结算。

本次不改变 score-based 结算 ABI，不引入按 `matchId` 无界遍历封锁。

## 2. 当前问题

当前代码中 `lockAt` 由 `matchStartTime - 5 minutes` 计算，并被多条用户/运营路径共同使用：

- `openMarket` 初始化 `MarketConfig.lockAt`；
- `updateOdds` 到达 `lockAt` 后拒绝更新；
- `previewSignal` 到达 `lockAt` 后拒绝预览；
- `placeBet` 的 `BettingValidationLib.validateMarketGuard` 到达 `lockAt` 后拒绝下注；
- `BettingPool._syncMarketLock` 与 `BettingSettlementModule._syncMarketLock` 会在被调用时按 `lockAt` 自动把 `Open` market 改为 `Locked`。

因此不能只改常量或只新增一个方法，必须删除时间触发的自动锁盘副作用。

## 3. 目标语义

### 3.1 market 状态

- `Open`：可下注、可预览、可更新赔率，直到 `block.timestamp >= matchEndTime`。
- `Locked`：由后端手动封锁产生；禁止下注、预览和赔率更新；比赛结束后仍可结算。
- `Settled / Refunded / Cancelled`：终态，保持现有语义。

### 3.2 `lockAt` 字段

为保持 storage 兼容，不删除 `MarketConfig.lockAt`：

- 开盘时默认写入 `lockAt = matchEndTime`；
- 手动封锁成功后写入 `lockAt = uint64(block.timestamp)`；
- 因此 `lockAt` 不再表示自动锁盘时间，而是“实际手动封锁时间；若未手动封锁，则等于比赛结束边界”。

### 3.3 手动封锁入口

新增：

```solidity
function lockMarket(bytes32 marketId) external;
```

建议权限与赔率运营路径一致：

- `BettingPool.lockMarket`：`onlyRole(OPERATOR_ROLE) + nonReentrant`；
- 实际重逻辑通过 `BettingSettlementModule` delegatecall 执行，控制 `BettingPool` runtime size。

关键校验：

- market 必须存在；
- market 必须为 `Open`；
- `block.timestamp <= matchEndTime`，超过比赛结束时间后应走结算，不再允许手动封锁。

状态变化：

- `market.status = MarketStatus.Locked`；
- `market.lockAt = uint64(block.timestamp)`；
- 调用 `LiquidityPool.closeMatchPoolDeposit(matchId)`；
- `marketOdds[marketId].quoteVersion += 1`，使旧 `QuoteGuardInput` 失效；
- 发出手动封锁事件。

说明：

- 对同一比赛下多个 market，不提供链上无界遍历封锁；后端如需整场封锁，应分页/逐个 market 调用；
- 可后续新增固定上限的批量封锁方法，但本次最小改造只新增单 market 入口。

## 4. 代码改造清单

### 4.1 `BettingPool.sol`

- 新增 `lockMarket(bytes32 marketId)` 外部入口；
- `openMarket` 初始化 `lockAt = matchEndTime`；
- `updateOdds` 改为：
  - market 不存在或终态或已到 `matchEndTime` 时关闭；
  - `status == Locked` 时锁盘；
  - 不再调用按时间自动锁盘的 `_syncMarketLock`；
- `previewSignal` 改为：
  - `block.timestamp >= matchEndTime` 时关闭；
  - `status == Locked` 时锁盘；
  - 不再检查 `block.timestamp >= lockAt`；
- `placeBet` 校验链路不再触发自动锁盘。

### 4.2 `BettingValidationLib.sol`

- `validateMarketGuard` 删除 `currentTimestamp >= lockAt` 的锁盘判断；
- 仅 `status == Locked` 返回 `MarketLocked`；
- `currentTimestamp >= matchEndTime` 返回 `MarketClosed`。

### 4.3 `BettingSettlementModule.sol`

- 新增 `lockMarket(bytes32 marketId)`；
- 删除或停用 `_syncMarketLock` 的时间自动锁盘逻辑；
- `settleMarketBetsByScore / finalizeMarketSettlement` 保持比赛结束后可执行，并允许 market 处于 `Open` 或 `Locked`。

### 4.4 `IBettingSettlementModule.sol`

- 新增 `lockMarket(bytes32 marketId)`。

### 4.5 `BettingPoolStorage.sol`

- 新增 `MarketManuallyLocked` 事件；
- 不新增 storage 字段。

### 4.6 `BettingConstants.sol`

- 删除不再使用的 `LOCK_BEFORE_START_SECONDS` 常量。

## 5. 测试清单

必须覆盖：

1. 未手动封锁时，比赛开始后但 `matchEndTime` 前仍可 `previewSignal / placeBet / updateOdds`；
2. 未手动封锁时，`block.timestamp >= matchEndTime` 后下注和预览均失败；
3. 手动封锁成功后，market 状态为 `Locked`，`lockAt` 等于封锁区块时间；
4. 手动封锁后，`previewSignal / placeBet / updateOdds` 均失败；
5. 手动封锁成功后，旧 `QuoteGuardInput` 因 `quoteVersion` 变化失效；
6. 手动封锁只能由 `OPERATOR_ROLE` 调用；
7. 手动封锁不能作用于不存在、非 `Open`、已超过 `matchEndTime` 的 market；
8. 未手动封锁的 market，比赛结束后可正常比分结算；
9. 已手动封锁的 market，比赛结束后可正常比分结算；
10. AH / OU / 1X2 line 矩阵测试继续通过。

## 7. 实施与验证结果

2026-06-02 已完成 Solidity 改造：

- 已删除开赛前 5 分钟自动锁盘常量与 `_syncMarketLock` 时间触发逻辑；
- `openMarket` 默认写入 `lockAt = matchEndTime`；
- `BettingPool.lockMarket(marketId)` 已作为 `OPERATOR_ROLE + nonReentrant` wrapper 对外暴露；
- `BettingSettlementModule.lockMarket(marketId)` 通过 delegatecall 更新 market 状态、`lockAt`、`quoteVersion`，发出 `MarketManuallyLocked`，并按 CEI 顺序调用 `LiquidityPool.closeMatchPoolDeposit(matchId)`；
- 未手动封锁时，`previewSignal / placeBet / updateOdds` 均以 `matchEndTime` 为关闭边界；
- 手动封锁后，下注、预览和赔率更新均被拒绝，赛后仍可正常结算。
