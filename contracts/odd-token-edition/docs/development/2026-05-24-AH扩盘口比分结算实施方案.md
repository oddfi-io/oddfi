# AH 扩盘口与比分结算实施方案

**日期：** 2026-05-24  
**状态：** 已实现
**基准：** `docs/research/2026-05-24-AH扩盘口最小改造调研.md`

## 1. 目标

本次改造目标：

1. AH 完整支持 `-0.25 / -0.5 / -0.75 / -1 / -1.25 / -1.5 / +0 / +0.25 / +0.5 / +0.75`。
2. OU 继续只支持 `1.5 / 2.5 / 3.5`，不扩 OU line。
3. 正常赛果结算统一由后端提交比分，合约根据 `marketType + line + homeScore + awayScore` 推导 1X2 / AH / OU 结算结果。
4. 删除旧全量结算和旧 winningOutcome 分批结算入口，避免后端同时维护多套结算方法。
5. full push、half win、half loss 的资金拆分全部由合约完成，后端不逐笔拼 `refundBets + settleMarketBets`。

## 2. AH line 编码

旧编码保持不变，只追加缺失 line：

| AH 盘口 | line |
|---|---:|
| -0.5 | 0 |
| -1 | 1 |
| -1.5 | 2 |
| -0.25 | 3 |
| -0.75 | 4 |
| -1.25 | 5 |
| +0 | 6 |
| +0.25 | 7 |
| +0.5 | 8 |
| +0.75 | 9 |

需要修改：

- `BettingConstants.ASIAN_HANDICAP_LINE_COUNT = 10`
- `MarketEnums.AhLine` 追加 `-0.25 / -0.75 / -1.25 / +0 / +0.25 / +0.5 / +0.75`
- `BettingOddsLib.validateTemplate` 继续通过 line count 校验 AH line
- `openMarket` 不新增入参，仍使用 `marketId = keccak256(abi.encode(matchId, marketType, line))`

## 3. 接口调整

### 3.1 删除接口

从 `BettingPool` 和 `IBettingSettlementModule` ABI 删除：

- `settleMarket(bytes32 marketId, uint8 resultKindRaw, uint8 winningOutcome)`
- `settleMarketBets(bytes32 marketId, uint8 winningOutcome, bytes32[] betIds)`
- `pushRefundMarket(bytes32 marketId, bytes32[] betIds)`

删除原因：

- `settleMarket` 会形成小 market 全量结算捷径，与统一分批比分结算冲突；
- 旧 `settleMarketBets` 依赖后端传 `winningOutcome`，无法覆盖 AH half win / half loss；
- `pushRefundMarket` 只支持 `line=1` 的 `-1` full push，扩 AH 后 full push 应统一走比分结算。

### 3.2 保留并改签名接口

```solidity
function finalizeMarketSettlement(bytes32 marketId, uint8 resultKindRaw) external;
```

语义：

- `resultKindRaw = 0`：正常结算收口，要求该 market 的 score-based 分批结算已经处理完全部 bet；零下注 market 可比赛结束后直接调用。
- `resultKindRaw = 1`：标记 market 为 `Refunded`，不遍历 bet、不计算 margin、不执行瀑布，后续真实退款继续走 `refundBets`。
- `resultKindRaw = 2`：标记 market 为 `Cancelled`，不遍历 bet、不计算 margin、不执行瀑布，后续真实退款继续走 `refundBets`。

统一校验：

- market 存在且未终态；
- `block.timestamp >= matchEndTime`；
- `resultKindRaw` 只能是 `0 / 1 / 2`；
- 若 score-based 分批结算已经开始，`resultKindRaw=1/2` 必须 revert；
- 若 `resultKindRaw=0` 且 market 有 bet，必须 `processedCount == marketBetIds[marketId].length`。

### 3.3 新增接口

```solidity
function settleMarketBetsByScore(
    bytes32 marketId,
    uint16 homeScore,
    uint16 awayScore,
    bytes32[] calldata betIds
) external;
```

语义：

- 仅用于正常赛果分批结算；
- 后端只提交最终比分和本批 betIds；
- 合约根据 market 模板推导每笔 bet 的 full win / full loss / full push / half win / half loss；
- 单批 `betIds.length` 继续复用 `FINALIZE_BATCH_HARD_CAP = 50`；
- 建议新增 `MAX_SETTLEMENT_SCORE = 50`，任一单队比分超过上限则 revert。

## 4. 存储与数据层修改

### 4.1 `MarketSettlementProgress`

旧结构中的 `winningOutcome` 不再适用，应改为记录比分：

```solidity
struct MarketSettlementProgress {
    bool active;
    uint16 homeScore;
    uint16 awayScore;
    uint256 processedCount;
    uint256 totalStake;
    uint256 grossPayout;
    uint256 loserStakes;
}
```

规则：

- 首批 `settleMarketBetsByScore` 写入 `homeScore / awayScore` 并设置 `active=true`；
- 后续批次必须使用同一比分，否则 revert；
- `finalizeMarketSettlement(marketId, 0)` 成功后必须执行 `delete marketSettlementProgress[marketId]`，避免该 market 残留 active / score / accumulated accounting；
- 当前测试网可重新部署，不要求为旧 proxy 存储布局做迁移兼容。

### 4.2 单笔结算结果结构

内部 resolver 建议返回单笔资金拆分，而不是返回单一 `winningOutcome`：

```solidity
struct BetSettlementBreakdown {
    uint256 refundStake;
    uint256 winStake;
    uint256 lossStake;
}
```

或使用等价内部结构，只要能表达 refund / win / loss 三段即可。

## 5. 比分结算推导

### 5.1 outcome 约定

- 1X2：`0 = home`，`1 = draw`，`2 = away`
- AH：`0 = home side with line`，`1 = away side against line`
- OU：`0 = Over`，`1 = Under`

AH 链上统一主队视角：

- `line` 永远表示主队让球；
- outcome `0` 永远表示主队按该 line 结算；
- outcome `1` 永远表示客队作为对手侧结算；
- 若数据源是客队视角，后端开盘前必须归一化为主队视角并重排 odds。

### 5.2 1X2

| 比分关系 | winning outcome |
|---|---:|
| `homeScore > awayScore` | 0 |
| `homeScore == awayScore` | 1 |
| `homeScore < awayScore` | 2 |

1X2 不产生 push / half。

### 5.3 OU

OU line 保持：

| line | OU | threshold half-goals |
|---:|---|---:|
| 0 | 1.5 | 3 |
| 1 | 2.5 | 5 |
| 2 | 3.5 | 7 |

推导：

```text
totalHalfGoals = (homeScore + awayScore) * 2
if totalHalfGoals > thresholdHalfGoals:
    outcome 0 Over full win
else:
    outcome 1 Under full win
```

OU 当前不产生 push / half。

### 5.4 AH

AH line quarter units：

| line | AH | quarter units |
|---:|---|---:|
| 0 | -0.5 | -2 |
| 1 | -1 | -4 |
| 2 | -1.5 | -6 |
| 3 | -0.25 | -1 |
| 4 | -0.75 | -3 |
| 5 | -1.25 | -5 |
| 6 | +0 | 0 |
| 7 | +0.25 | 1 |
| 8 | +0.5 | 2 |
| 9 | +0.75 | 3 |

以 outcome 0 为视角，`scoreDiff = homeScore - awayScore`。

| AH line | scoreDiff 条件 | outcome 0 结果 |
|---|---|---|
| -0.25 | `>= 1` | full win |
| -0.25 | `= 0` | half loss |
| -0.25 | `<= -1` | full loss |
| -0.5 | `>= 1` | full win |
| -0.5 | `<= 0` | full loss |
| -0.75 | `>= 2` | full win |
| -0.75 | `= 1` | half win |
| -0.75 | `<= 0` | full loss |
| -1 | `>= 2` | full win |
| -1 | `= 1` | full push |
| -1 | `<= 0` | full loss |
| -1.25 | `>= 2` | full win |
| -1.25 | `= 1` | half loss |
| -1.25 | `<= 0` | full loss |
| -1.5 | `>= 2` | full win |
| -1.5 | `<= 1` | full loss |
| +0 | `>= 1` | full win |
| +0 | `= 0` | full push |
| +0 | `<= -1` | full loss |
| +0.25 | `>= 1` | full win |
| +0.25 | `= 0` | half win |
| +0.25 | `<= -1` | full loss |
| +0.5 | `>= 0` | full win |
| +0.5 | `<= -1` | full loss |
| +0.75 | `>= 0` | full win |
| +0.75 | `= -1` | half loss |
| +0.75 | `<= -2` | full loss |

outcome 1 自动取反：

- outcome 0 full win -> outcome 1 full loss
- outcome 0 full loss -> outcome 1 full win
- outcome 0 full push -> outcome 1 full push
- outcome 0 half win -> outcome 1 half loss
- outcome 0 half loss -> outcome 1 half win

## 6. 资金拆分与账务

每笔 pending bet 先计算：

```text
currentStake = acceptedAmount - refundedAmount
releasedPotentialPayout = currentStake * lockedOdds / ODDS_RATE_SCALE
```

### 6.1 拆分表

| 单笔结果 | refundStake | winStake | lossStake |
|---|---:|---:|---:|
| full win | 0 | currentStake | 0 |
| full loss | 0 | 0 | currentStake |
| full push | currentStake | 0 | 0 |
| half win | halfStake + remainder | halfStake | 0 |
| half loss | halfStake + remainder | 0 | halfStake |

half 拆分：

```text
halfStake = currentStake / 2
remainder = currentStake - halfStake * 2
```

余数统一归入 `refundStake`，避免多计 win/loss、margin 或 payout tax。

### 6.2 账务规则

- `refundStake`：结算交易中立即退回用户，增加 `bet.refundedAmount`；若全额退完，bet 为 `Refunded`；不收派奖税。
- `winStake`：写入 `claimablePayout = winStake * lockedOdds / ODDS_RATE_SCALE`；bet 为 `WonUnclaimed`；派奖税只对该 gross payout 计算。
- `lossStake`：计入 `loserStakes`；bet 为 `Lost`。
- `SettlementContext.totalStake` 只累计 `winStake + lossStake`，不包含 push/refund 部分。
- score-based 分批结算对每笔 bet 只释放一次风险：`unsettledStake` 按 `currentStake` 释放，`potentialPayoutCommitted` 按 `releasedPotentialPayout` 释放。
- score settlement 中的 `refundStake` 只做转账和 `refundedAmount` 记录，不复用 `_applyRefundRiskRollback`，避免二次扣减风险账本。

AH full push 属于正常赛果结算：

- market 最终为 `Settled`；
- bet 可为 `Refunded`；
- 不调用 `refundBets`；
- 不产生 `claimablePayout`、payout tax、margin、瀑布。

## 7. 事件

删除旧事件：

- `MarketSettled`
- `MarketSettlementBatchProcessed`
- `PushRefunded`

新增或替换：

```solidity
event MarketSettlementScoreBatchProcessed(
    bytes32 indexed marketId,
    uint16 homeScore,
    uint16 awayScore,
    uint256 processedCount,
    uint256 totalBetCount
);

event MarketSettlementFinalized(
    bytes32 indexed marketId,
    uint8 resultKind,
    bool scoreSettled,
    uint16 homeScore,
    uint16 awayScore,
    uint256 grossPayout,
    uint256 lpMarginShare,
    uint256 platformMarginShare,
    uint256 quoteVersion
);
```

事件语义：

- `scoreSettled=true` 表示该 market 经过 `settleMarketBetsByScore` 分批结算，`homeScore / awayScore` 为本 market 结算比分；
- 零下注正常结算、`Refunded`、`Cancelled` 的 `scoreSettled=false`，事件中的比分字段不作为真实比分解释；
- 索引侧不再依赖旧 `winningOutcome` 字段还原比分。

## 9. 测试矩阵

### 9.1 开盘模板

- AH `line=0..9` 可开盘。
- AH `line=10` revert。
- OU `line=0..2` 保持可用。
- OU `line=3` revert。
- 1X2 只允许 `line=0`。

### 9.2 赛果推导

- 1X2：主胜 / 平 / 客胜。
- OU：`1.5 / 2.5 / 3.5` 的 Over / Under。
- AH 每条 line 覆盖 full win / full loss。
- AH 有 push 或 half 边界的 line 覆盖对应边界：
  - `+0` draw -> full push
  - `-1` 主赢 1 球 -> full push
  - `-0.25` draw -> outcome 0 half loss
  - `-0.75` 主赢 1 球 -> outcome 0 half win
  - `-1.25` 主赢 1 球 -> outcome 0 half loss
  - `+0.25` draw -> outcome 0 half win
  - `+0.75` 客队赢 1 球 -> outcome 0 half loss

### 9.3 分批结算

- 首批记录比分。
- 第二批同比分成功。
- 第二批不同比分 revert。
- 重复 betId revert。
- betId 不属于 market revert。
- `betIds.length == 0` revert。
- `betIds.length > FINALIZE_BATCH_HARD_CAP` revert。
- `homeScore / awayScore > MAX_SETTLEMENT_SCORE` revert。
- 未处理完全部 bet 时 `finalizeMarketSettlement(marketId,0)` revert。
- 处理完全部 bet 后 finalize 成功。
- finalize 成功后 `marketSettlementProgress[marketId]` 被删除，后续不能再读取到 active / score / accumulated accounting。

### 9.4 终态与退款

- 零下注 market 比赛结束后可直接 `finalizeMarketSettlement(marketId,0)`，market 为 `Settled`。
- `finalizeMarketSettlement(marketId,0/1/2)` 在赛前或赛中 revert。
- score-based 分批已经开始后，`finalizeMarketSettlement(marketId,1/2)` revert。
- `finalizeMarketSettlement(marketId,1)` 后 market 为 `Refunded`，后续 `refundBets` 可分批退款。
- `finalizeMarketSettlement(marketId,2)` 后 market 为 `Cancelled`，后续 `refundBets` 可分批退款。
- full push 走 `resultKindRaw=0`，market 为 `Settled`，对应 bet 为 `Refunded`。

### 9.5 资金正确性

- half win 只对 winning half 计算 `claimablePayout` 和 payout tax。
- half loss 的 refund half 不进入 margin / loserStakes。
- full push 不产生 `claimablePayout`、payout tax、margin、瀑布。
- 奇数最小单位本金下，half 拆分余数归 `refundStake`。
- score settlement 不复用 `_applyRefundRiskRollback` 导致风险账本二次扣减。

### 9.6 ABI 删除

- 旧 `settleMarket(...)` 不在 `BettingPool` ABI。
- 旧 `settleMarketBets(..., winningOutcome, ...)` 不在 `BettingPool` ABI。
- 旧 `pushRefundMarket(...)` 不在 `BettingPool` ABI。
- `IBettingSettlementModule` 同步删除上述旧入口。

## 10. 待确认点

1. 零下注 market 直接 `finalizeMarketSettlement(marketId,0)` 时不携带比分；如果索引侧要求所有 `Settled` market 都有链上比分，需要额外设计比分记录入口或调整 finalize 参数。
2. `MAX_SETTLEMENT_SCORE = 50` 是建议值；如产品希望允许更极端比分，需要实现前调整。
3. 半赢/半输不新增 `BetSettlementState`，用 `refundedAmount + WonUnclaimed/Lost` 表达；如果前端需要直接区分 half win / half loss，需要另加事件字段或状态字段。
